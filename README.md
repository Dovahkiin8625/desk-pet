# 桌面宠物（Live2D）

Windows 桌面上的 Live2D 桌宠。默认形象为 Live2D 官方样例角色 Haru。

> **许可提示：** 官方样例模型（Haru / Hiyori / Mao / Mark / Natori / Ren / Rice / Wanko）
> **限非商业用途**；Cubism Core 为 Live2D 专有许可代码。
> `npm run setup` 会把官方样例素材下载到你的机器上，
> 分发前请先读 [NOTICE](./NOTICE)。

## 功能

- 透明无边框、置顶的桌宠窗口
- Live2D 待机动画、呼吸、眨眼、物理效果
- 视线跟随鼠标（**鼠标不在桌宠身上时也看着它**）
- 摸头 / 点击身体触发不同表情与动作
- 情绪系统：心情随互动起伏，久不理它会犯困，被连续猛点会生气
- 按住拖拽移动，位置自动记忆
- **可点击区域与拖动边界都跟着形象走**：Live2D 贴图四周那圈透明留白
  不再吃掉鼠标点击（点那里桌面照常响应），角色也能真的拖到屏幕顶
- **按住 Ctrl + 滚轮调整桌宠大小**（也可以在设置窗口里拖滑块）
- 系统托盘菜单（显示隐藏 / 设置 / 退出）
- **插件面板**：左键点一下桌宠，弹出搜索框，模糊搜索后回车打开插件界面
  （待办、提醒、番茄钟、天气、系统状态、剪贴板、录屏、聊天记录）
- **能搜本机程序**：同一个搜索框里也能搜本机装的东西（开始菜单、PATH、程序目录），
  回车就启动，像 uTools 那样
- **能聊天**：在那个输入框里直接对桌宠说话，回复在桌宠旁边的气泡里**逐字**冒出来
  （按你设定的人设回答，会记住你说过的事，情绪也会跟着变）
- 说话气泡：桌宠把要说的话显示在头顶
- 语音播报（MiniMax TTS）+ 口型同步，音色与 API Key 可配置
- **点桌宠时它会说话**：用你设定的音色念一句台词（台词可以自己写），
  也可以让它保留 Live2D 模型自带的声音
- 语音与提示音共用一个**总音量**滑块
- **开机自启**：登录 Windows 后自动拉起
- **全局快捷键**：一个组合键呼出/隐藏桌宠（默认 `Control+Shift+D`，可改）；
  另一个组合键**唤醒输入框**（唤出搜索框并把焦点放进去，可以直接打字，默认不设）
- **鼠标穿透**：点不到桌宠，桌面照常操作（桌宠仍跟着光标转头）
- **边缘吸附 + 贴边隐藏**：拖到屏幕边缘自动贴齐，可滑出屏幕只留一条边
- 多显示器与 DPI 适配
- 运行时切换形象
- **导入自己的 Live2D 模型**：设置窗口里点「导入模型…」选一个模型文件夹，
  复制到用户数据目录、校验、注册并立即切换；重启后依然在，也能随时删掉。
  Cubism 4 与 Cubism 2 老格式都支持
  （见 [添加自己的形象](#添加自己的形象)）

## 环境要求

- Windows 11
- Node.js ≥ 20

## 快速开始

```bash
npm install     # 安装依赖（含 Electron 自动下载）
npm run setup   # 下载 Live2D 官方样例模型 + 生成托盘图标
npm start       # 启动桌宠
```

`npm run setup` 需要联网（从 GitHub 拉取官方样例资源）。执行一次后资源会缓存在
`assets/live2d/models/` 下，之后可离线重复运行。

> `npm run setup` 下载的是 Live2D 官方样例素材，**限非商业用途**；
> Cubism Core（运行时从 `vendor/live2d/` 加载，官方 SDK 5-r.5 自带的那份）
> 是 Live2D 专有许可代码。详见 [NOTICE](./NOTICE)。
>
> **模型二进制不在版本库里。** 仓库只提交手写的 `pet.json` 清单，
> 各样例的 `.moc3`、贴图、动作等二进制由 `npm run setup` 下载。
> 全新克隆的仓库必须先跑一次 `npm run setup`，否则桌宠窗口里没有任何模型。

## 插件面板（左键点桌宠）

**左键点一下桌宠**，桌宠旁边会弹出一个搜索框：

```
┌─ 插件面板 ─────────────────┐
│ ✨  待办▌                  │
├────────────────────────────┤
│ ✓  待办       查看与添加待办 │
│ ⏰  提醒       到点提醒你做事 │
│ 🍅 番茄钟      专注与休息计时 │
└────────────────────────────┘
```

打几个字就能**模糊搜索**——中文名、英文、拼音都认（「待办」「todo」「daiban」都行）。
点一下结果或按 **Enter** 就打开那个插件的界面（同一个窗口换内容，**Esc** 回到搜索）。

这个框**不止是搜索**：它也能直接跟桌宠说话。框里的提示写着
「搜索插件、程序，或跟桌宠说点什么…」——回车时如果匹配不到插件（或按 **Ctrl+Enter**），
这句话就发给桌宠，回复出现在桌宠旁边的气泡里。

同一个框里还能**搜本机的程序**：输入「note」能搜到记事本，回车就启动它。
索引扫的是开始菜单、PATH 与程序目录（`C:\Program Files` 等），
应用启动时在后台扫好，按需刷新。

| 插件 | 说明 |
| --- | --- |
| 待办 | 加一条、点一下完成、清除已完成 |
| 提醒 | 「30分钟后喝水」「2小时后」「14:30」「明天 9:00」都认 |
| 番茄钟 | 25 分钟专注 / 5 分钟休息，可暂停继续重置 |
| 天气 | 填一个城市名后开启，定时播报（open-meteo，免密钥） |
| 剪贴板 | 复制内容时提示一句（**内容不落盘**） |
| 系统状态 | CPU、内存、温度、电源（还能变成桌面小部件） |

另有两项**内置功能**，它们不是插件（关不掉、也不在插件目录里），
但同样能在面板里搜到、打开：**设置**（开设置窗口）与**聊天记录**
（和桌宠说过的话，可一键清空）。

插件界面里直接改数据（加待办、勾完成、开关剪贴板助手……），
改完立刻反映在界面上。桌宠自己的**说话气泡**只负责显示它说了什么，
点击穿透、不挡桌面的操作。

**每个插件管自己的设置**：天气插件里设城市、开定时播报，
剪贴板插件里开关助手，系统状态插件里开「过热时提醒」——
这些开关**不在设置窗口里**（设置窗口里放一份旧值会把插件页面改过的设置覆盖回去）。
设置窗口只管**应用级别**的东西，包括「装了哪些插件、开着哪些」。

待办、提醒、番茄钟的状态存在 `userData/assistant.json`，退出后仍然保留。

## 插件系统（可插拔）

插件**不是**代码里写死的一份清单，而是磁盘上的目录：加一个目录就多一个插件，
删掉一个目录就少一个。宿主（`src/main/plugins/`）扫一遍插件根目录，
把每个子目录读成一个插件——清单坏了的插件只影响它自己，会被跳过并在日志里留痕。

```text
plugins/                  内置插件（随程序分发）
  todos/
    plugin.json           清单：名字、图标、关键词、窗口规格
    main.js               入口：导出默认函数，返回插件实例
  system/
    plugin.json
    main.js
    widget.html           插件**自己的**页面（小部件用）
    widget.js
```

用户自己的插件放 `userData/plugins/<插件名>/`，结构完全一样；
同名时**用户的那个算数**（用户明确装了它）。

### 清单（plugin.json）

```json
{
  "id": "system",
  "name": "系统状态",
  "icon": "📊",
  "description": "CPU、内存、温度、电源",
  "keywords": ["system", "cpu", "状态", "内存"],
  "entry": "main.js",
  "window": { "title": "系统状态", "width": 320, "height": 300, "refreshMs": 1000 },
  "widget": { "title": "系统监控", "width": 216, "height": 108, "page": "widget.html", "refreshMs": 1000 }
}
```

- `id` 必须与**目录名一致**，只能用小写字母、数字与连字符；
- `entry` 与 `page` 都是相对路径，**不能**跑到插件目录外面去；
- 写了 `window` 段，面板上才有「在新窗口打开」按钮；写了 `widget` 段才有「变成小部件」；
- `refreshMs` 是周期刷新的间隔（毫秒）：小部件靠它活着（系统监控每秒变一次）。

### 插件能拿到什么

入口导出的是一个工厂函数，它收到一个**上下文**（ctx），拿到的全在这儿：

```js
export default function createTodosPlugin() {
  const page = (ctx) =>
    ctx.ui.makePage({
      pluginId: 'todos',
      title: '待办',
      blocks: [ctx.ui.textBlock('……'), ctx.ui.inputBlock('add', '要做什么？', '添加')],
    });

  return {
    page,                                   // 面板里的界面（可以是 async）
    action(ctx, actionId, value) {          // 界面里的动作 → 返回新的页面
      return { ...page(ctx), status: '加好了' };
    },
    data(ctx) { return { cpu: 42 }; },      // 自定义页面打开时的数据
    tick(ctx) { return { cpu: 43 }; },      // 自定义页面的周期数据
    act(ctx, actionId, payload) { return null; }, // 自定义页面里的动作
  };
}
```

| ctx 里的 | 是什么 |
| --- | --- |
| `ui` | 界面积木：`makePage` / `textBlock` / `listBlock` / `inputBlock` / `buttonsBlock` / `toggleBlock` / `emptyBlock` / `messagesBlock` |
| `assistant` | 助理总控：待办、提醒、番茄钟、天气、剪贴板、系统状态的读写都在它那儿 |
| `openSettings()` | 打开设置窗口 |
| `update(page)` | 异步动作完成后再刷新一次页面（天气查询那种） |
| `host` | 宿主能力：`listAll()` / `setEnabled()` / `openWindow()` / `closeWindow()` |
| `plugin` | 这个插件自己的 id、清单与目录 |

插件拿到的**接口**只有上面这些。不过要说清楚：插件的代码就**跑在主进程里**
（它是个普通的 Node 模块），想 import 什么就 import 什么——**这里没有沙箱**。
插件与宿主之间靠的是约定，不是权限边界。

### 独立窗口与桌面小部件

插件界面默认待在面板里。清单里写了 `window` 段之后，面板上会出现 **↗**
（在新窗口打开）；写了 `widget` 段还会多一个 **▣**（变成桌面小部件）。

- **独立窗口**：自己的窗口，能调整大小、能拖到别处；标题栏上有 **📌** 置顶开关；
- **桌面小部件**：无边框、透明、常驻桌面（像系统监控那样挂在那儿），整块可以拖。

两者是同一个窗口的两种样子，可以来回切。插件没有自己的页面时，
窗口里套的是**通用界面**（`src/renderer/plugin-window/`）——
上面是插件的标题与窗口按钮，下面是插件的声明式页面，与面板里长得一样。

插件自己写了页面（清单里的 `page`）时，走的是插件自己的 HTML：
它自己画界面，宿主只负责按 `refreshMs` 喂数据（`tick`）、
以及替它转发动作（`act`）。页面里能用 `window.plugin`：

```js
window.plugin.onTick((data) => { /* 周期数据到了 */ });
window.plugin.data().then((data) => { /* 打开时的第一份数据 */ });
window.plugin.act('click', { id: 1 });
window.plugin.window.setAlwaysOnTop(true);
window.plugin.window.setMode('widget');
window.plugin.window.close();
```

### 开关插件

设置窗口的「**插件**」分区里点一下就能开关某个插件：关掉的插件不出现在搜索结果里，
它的窗口也会跟着关。状态存在 `userData/plugins.json`。

> 商店（在线安装插件）**还没做**：现在只有「把插件目录放进去」这一条路。

### 录屏

面板里搜「**录屏**」：

- **三种录法**：全屏、选区（像截图那样在屏幕上拉一个框）、窗口；
- **录哪一块**：选了之后，面板里会列出能录的显示器和窗口，点一个就是它；
- **声音**：麦克风与扬声器可以分开开，也可以一起开（自动混音）；
- **两种格式**：MP4（H.264 + AAC）或 GIF（**GIF 存不了声音**）；
- **存放位置**：默认是系统的「视频」文件夹，可以在插件里改；
- **快捷键**：默认 `Control+Shift+R`，可以改。
  **只有录屏的工作台窗口开着的时候才生效**——关掉窗口就把这个组合键让回给别的程序；
- 录制时桌面上会出现一个置顶的小控制条，显示录了多久，点「停止」就停；
- 录着录着被录的那个窗口被关掉了？录制会自己停下来，已经录的照样存下来。

## 设置窗口

托盘菜单或桌宠右键菜单里的「设置…」打开（面板里搜「设置」也行）。
左边是分区目录，右边一次只显示一节：

```text
┌──────────────┬────────────────────────────────────────┐
│ 外观   Haru  │  外观                                  │
│ 助理    3/3  │  桌宠长什么样，在桌面上占多大。           │
│ 语音    已关  │  ──────────────────────────────────    │
│ 对话    缺 Key│  形象   [Haru                   ▾]      │
│ 记忆    3 条 │  缩放   ───────●──────      1.00x      │
│ 插件    6/6  │                                        │
├──────────────┴────────────────────────────────────────┤
│ 设置即时生效并自动保存                    已保存 ✓    │
└───────────────────────────────────────────────────────┘
```

目录右边那一列是**状态摘要**：不进每一节也看得出现在是什么状态
（助理开了几项、语音有没有 Key、记住几条事实、几个插件开着）。

设置**即时生效并自动保存**；API Key 存在 `userData/credentials.json`，
界面上只显示掩码（`****abcd`），永远不回显明文。

### 哪些设置在设置窗口，哪些在插件里

设置窗口管的是**应用级别**的东西：桌宠长什么样、助理什么时候开口、
语音与对话怎么配、开机自启与快捷键，以及**装了哪些插件、开着哪些**。

**某个插件自己的配置不在这里**——它在那个插件的页面里：

| 插件 | 它的设置在哪 |
| --- | --- |
| 剪贴板 | 面板里打开「剪贴板」→ 开关「剪贴板助手」 |
| 天气 | 面板里打开「天气」→ 填城市、开关定时播报 |
| 系统状态 | 面板里打开「系统状态」→ 开关「过热时提醒我」 |
| 录屏 | 面板里打开「录屏」→ 模式/声音/格式/存放位置；点「设置…」打开工作台改快捷键 |

这样安排有个实在的好处：设置窗口**不会**把插件页面改过的设置覆盖回去
（它连这些字段都不碰）。

## 系统（开机自启 / 快捷键 / 穿透 / 贴边）

设置窗口的「**系统**」分区（目录里最后一项）管的是桌宠与 Windows 的关系：

| 项 | 说明 |
| --- | --- |
| 开机自启 | 登录 Windows 后自动拉起桌宠。默认关。写注册表失败时这里会写出原因，开关也会自己退回去 |
| 全局快捷键 | 默认 `Control+Shift+D`，点「重新录制」按新的组合。**至少要带一个修饰键**（Ctrl / Alt / Shift）——裸键会劫持你所有的字母键 |
| 输入框快捷键 | **默认不设**。设好之后按这个组合会唤出插件面板，焦点直接落在搜索框里，可以立刻打字。点「清除」可以把它撤掉 |
| 鼠标穿透 | 开了点不到桌宠，桌面照常操作；桌宠仍跟着光标转头。托盘菜单里也有这个勾选项 |
| 边缘吸附 | 拖到屏幕边缘附近时自动贴齐（默认开） |
| 贴边隐藏 | 贴齐后滑出屏幕，只留一条边；**拖那条边可以把它拽回来**（默认关） |

**快捷键被别的程序占用时**（Windows 上这是静默失败，接口不报错），
设置窗口会写明「该组合已被其他程序占用」，并写出**当前设置的组合**是什么。
换组合时是先注册新的、成功了再注销旧的，所以**换组合失败时原来那个组合仍然有效**；
但如果应用**启动时**就没注册上（那个组合被别的程序先占了），
界面不会宣称它「仍然有效」——那种情况下它确实还没生效。

两个快捷键**不能设成同一个组合**：设置窗口会说「这个组合已经被『呼出 / 隐藏桌宠』用了」，
而不是含糊地说「被其他程序占用」——占着它的是这个应用自己。

「唤醒输入框」那个快捷键**默认不设**：多抢一个全局组合不是用户要求的行为，
要用的时候自己在设置里录一个。桌宠被藏起来时按它，桌宠会先被请出来，
免得面板变成一块悬在屏幕上的输入框。

桌宠停靠在屏幕边缘外时，托盘菜单与右键菜单里会多出一项「**取回桌宠**」；
不开穿透的话，也可以直接拖那条边把它拽回来。

> 开机自启与全局快捷键**只能人工验证**（E2E 不碰注册表、不按全局键），
> 详见下面的「人工验证清单」。

## 和桌宠聊天

面板的输入框**也能直接对桌宠说话**：

- 输入的话**匹配不到任何插件**（比如「在吗」）→ 回车＝发给桌宠；
- 匹配到插件 → 回车＝打开那个插件；
- **Ctrl+Enter 永远发给桌宠**（哪怕这句话也匹配得到插件）。

桌宠的回复显示在它旁边的**气泡**里，**一个字一个字地冒出来**。

在设置窗口的「对话」一节里可以改：

| 项 | 说明 |
| --- | --- |
| 接口地址 / 模型 | 走 OpenAI 兼容协议，填别的服务商也能用（模型名以那家的控制台为准） |
| 温度 / 回复长度 | 越大越啰嗦 |
| 对话 Key | 留空＝沿用上面那个 MiniMax Key |
| 人设 | 名字、性格、背景——决定它怎么说话 |
| 主动搭话 | 默认关。开了之后它会按间隔主动开口（深夜不打扰） |

桌宠会记住你说的事（短期记最近几轮，长期记「事实」），
回复里的情绪也会反映到它的表情上。

桌宠记住了什么，可以在设置窗口的**「记忆」**一节里逐条查看、一键清空。

> 聊天记录是**内置功能**（不是插件）：在面板里搜「聊天记录」就能打开。

## 语音播报

语音走 **MiniMax TTS**。在设置窗口里填 API Key、选音色、调语速即可；
不填就只显示文字气泡，不出声。

- API Key 存在 `userData/credentials.json`，**不进渲染层**，界面上只显示掩码。
- 音色是自由输入 + 建议列表：建议表里的 id 都验过能用，但新音色随时会加，
  所以也可以直接填任意合法的 `voice_id`。
- 开发期也可以把 key 放在项目根目录的 `minimax-api-key`（已被 `.gitignore` 排除）。
- 「语音」分区里还有一个**总音量**滑块——提示音与桌宠说话**一起**受它管
  （总音量走的是渲染层的主增益，不是 TTS 的 `vol` 参数）。

### 点桌宠时它说什么

「语音 → 点桌宠时」这一节管的是**点一下桌宠**的反应：

| 开关 | 效果 |
| --- | --- |
| 点桌宠时说话 | 开：点一下，桌宠念一句台词；关：不念台词（模型自带的声音照旧） |
| 也用 Live2D 模型自带的声音 | 开：模型自带的 wav 和生成的台词**一起随机抽**；关：只用生成的台词 |
| 台词（每行一句） | 自己写台词，最多 20 句、每句 60 字 |

- **台词的语音是事先合成好的**：应用启动后、改了音色或台词后，
  都会在后台把每句台词合成一遍存到本地（`userData/tts-cache/tap/`）。
  点击时读的是本地缓存——**不调接口**，也没有等待。
- 换音色不用手动清缓存：缓存按「台词+音色+语速+音量+音高」的内容哈希存，
  换了就自动重新生成。
- **点一下只出一声**：3 秒内连点不会再念第二句（语音会叠在一起）。
- **模型自带的声音是兜底**：生成的语音顶不上来时（没配 Key、语音没开、
  没有台词），桌宠的行为和这个功能存在之前一模一样——模型自己出声。
  只有生成的语音真的顶上来了，模型自带的声音才可能被替换掉。
- 台词的气泡摆在**脚下**——点桌宠时插件面板在头顶，两者不重叠。

## 内置形象

程序自带 8 个 Live2D 官方样例角色，设置窗口的「外观 → 形象」里可以直接切换：

| 形象 | 表情 | 动作组 | 备注 |
| --- | --- | --- | --- |
| Haru | 8 个（`F01`…`F08`） | Idle / TapBody | 默认形象 |
| Hiyori | 无 | Idle / TapBody | 只有动作，没有表情文件 |
| Mao | 8 个（`exp_01`…`exp_08`） | Idle / TapBody | 表情语义见下方「语义键」 |

- **模型文件不随程序分发**：`npm run setup` 从 Live2D 官方仓库把它们下载到
  `assets/live2d/models/`（每个约 9MB）。仓库里只保留每个模型手写的清单
  `pet.json`（表情与动作的语义映射）。
- **预制的形象也能移除**：在设置窗口里选中它，点旁边的 **「删除」** 即可从
  形象列表里去掉。移除只是记一笔账（`<userData>/live2d/removed.json`），
  程序目录里的模型文件不会被删——装到 `Program Files` 下本来也没有写权限。
  想让它回来，删掉那个文件即可。
- **至少要保留一个形象**：删到只剩最后一个时不允许再删，否则桌宠就没有
  形象可画了。

## 添加自己的形象

有两种方式。普通用户用第一种，开发者用第二种。

### 方式一：设置窗口里「导入模型…」（推荐）

设置 → **外观** → 形象那一行右侧的 **「导入模型…」**：

1. 选一个 Live2D 模型**文件夹**（不是单个文件——模型是一整套文件：
   设置清单、`.moc3`/`.moc`、纹理、动作、表情）。
2. 应用把它复制到用户数据目录 `<userData>/live2d/models/<id>/`，
   校验完整性，注册进形象列表，并**立即切换**到这个新形象。
3. 导入的形象会标注「（导入）」，可以随时用旁边的 **「删除」** 按钮删掉。

导入的形象**重启后依然在**（存在用户数据目录里，不在程序安装目录），
因此装到 `Program Files` 下也没有问题。

几点说明：

- **两种 Cubism 格式都支持**：
  - Cubism 4：`.model3.json` + `.moc3`（官方样例 Haru / Natori 就是这种）
  - Cubism 2：老格式，`.model.json` 之类 + `.moc`
    （比如仓库里的 `assets/live2d/models/DSR50`——它的设置文件叫 `model0.json`，
    动作文件还是**文本**格式：`# Live2D Animator Motion Data`）

  格式是按设置文件的**内容**判别的，不是文件名：老模型的设置文件叫什么都行。
- **模型根目录 = 设置文件所在的目录。** 纹理与动作的相对路径是按它解析的，
  所以可以直接选装着模型文件夹的父目录——应用会自动认出里面那层。
- 导入的模型**默认不写表情语义映射**（原因见下方「降级」一节）：
  它会走既有的降级路径，只播动作、不套表情。
  但**你自带的 `pet.json` 会被原样保留**——模型文件夹里已经放了一份的话，
  应用不会覆盖它，里面写好的表情/动作语义映射照常生效
  （前提是它的 `model3` / `model2` 字段指向真实存在的文件，否则导入会报错说明是哪个文件）。
  清单格式见下方「注册表条目格式」一节。
- 复制有上限（200 MB / 2000 个文件）：文件夹选择器允许误选整个家目录，
  没有上限的话一次手滑就是几十上百 GB。

### 方式二：手动放进项目里（开发者）

1. 把模型目录放到 `assets/live2d/models/<id>/`（需含 `.model3.json`、`.moc3`、纹理等）
2. 在 `assets/live2d/index.json` 注册该形象
3. 可选：写一份 `pet.json` 清单，把表情/动作映射到语义键

### 注册表条目格式

`assets/live2d/index.json` 里每个形象是一个对象：

```jsonc
{
  "models": [
    {
      "id": "haru",                    // 唯一标识；设置里存的就是它
      "name": "Haru",                  // 下拉框里显示的名字
      "manifest": "haru/pet.json",     // 清单路径（相对 models/ 目录）；缺省为 "<id>/pet.json"
      "model3": "Haru.model3.json"     // model3 文件名（相对 <id>/ 目录）；缺省为 "<id>.model3.json"
    },
    {
      // Cubism 2 的老模型：设置文件用 model2 字段点名。
      // 有 model2 就是 Cubism 2（不会再去补 model3 默认值）。
      "id": "dsr50",
      "name": "DSR50",
      "manifest": "dsr50/pet.json",
      "model2": "model0.json"
    }
  ]
}
```

只有 `id` 是必须的：`name` 缺省用 `id`，`manifest` / `model3` 缺省按上面的规则推导。
没有 `id` 的条目会被忽略并在终端里留痕。

`model3` 与 `model2` 是**互斥**的：有 `model2` 就是 Cubism 2，
没有 `model2` 就是 Cubism 4（`model3` 缺省为 `<id>.model3.json`）。

清单缺失时应用会自动从设置文件探测能力并降级运行，因此**只放目录也能加载**。

清单格式见 `assets/live2d/models/haru/pet.json`：

```jsonc
{
  "id": "haru",                    // 与注册表里的 id 一致（以注册表为准）
  "name": "Haru",                  // 显示名
  "model3": "Haru.model3.json",    // 目录下的设置文件名（Cubism 2 用 "model2"）
  "viewport": { "width": 300, "height": 560 },        // 见下方说明
  "fit": { "scale": 1.0, "anchor": [0.5, 1.0], "offset": [0, 0] },  // 适配与摆位
  "expressions": { /* 语义键 → 模型自己的表情名 */ },
  "motions": { /* 语义键 → { group, index } */ }
}
```

各字段的用法：

- `viewport`：桌宠窗口的视口尺寸。**窗口尺寸目前写死在 `src/main/window.js`（300×560）**，
  清单里的这个值只是与它保持一致的对照，改它不会改变窗口大小。
- `fit.scale`：模型在视口内的基础缩放（还会再乘设置里的用户缩放）。
- `fit.anchor`：模型锚点，`[x, y]`，默认 `[0.5, 1.0]`（水平居中、贴底）。
- `fit.offset`：摆位偏移，单位是视口宽/高的比例，`[0, 0]` 表示不偏移。

### 语义键

`pet.json` 里用的是**语义键**，不是模型自己的表情名/动作名——这样换模型时
交互逻辑不用改。清单里可用的语义键如下（`应用会触发` 一列标明应用当前真正会用到哪些）：

| 类别 | 语义键 | 应用会触发 |
| --- | --- | --- |
| 表情 | `normal` | 空闲时回到中性表情 |
| 表情 | `happy` | 摸头（命中 `Head` 区）；待办完成、提醒送达 |
| 表情 | `smile` | 点击身体（命中 `Body` 区） |
| 表情 | `shy` | 被夸奖、桌宠说话时 |
| 表情 | `surprised` | 被拖拽、提醒突然弹出 |
| 表情 | `sad` | 长时间没人理、系统过热 |
| 表情 | `angry` | 2 秒内被连续点 3 次以上 |
| 表情 | `tired` | 3 分钟没有任何互动 |
| 动作 | `idle` | 空闲时播放的动作（不写 `index`，由库随机挑一个） |
| 动作 | `tapHead` | 摸头时的动作 |
| 动作 | `tapBody` | 点击身体时的动作 |
| 动作 | `drag` | 开始拖拽时的动作 |

语义键缺失时不会报错：**未映射的表情语义一律不套表情，只播对应动作**，
动作组不存在则跳过该动作。（spec §4.4 的降级表：「语义缺失 → 退化为播放对应动作；
仍缺失 → 仅播动作」。）

> Natori 的清单里 `happy` 与 `smile` 都映射到 `Smile`：
> 选 Natori 时摸头与点击身体的**表情相同**，只有动作不同。
>
> `tired` 有 Haru（`F04`：半闭下垂的眼 + 平嘴，目视确认过是慵懒/困倦的脸）、
> Mao（`exp_03`：闭眼）与 Ren（`exp_03`：闭眼）。
> **Natori 不映射 `tired`**，所以选 Natori 时犯困只会播动作、不套表情。

**降级（没有 `pet.json`）时只探测能力、不猜语义**——按序号猜会让「摸头」触发生气的脸。
唯一的例外是 `normal`：降级时**按名字**匹配模型里叫 `Normal` 的表情
（Natori 有；Haru 的表情名是 `F01`…`F08`，没有）。
匹配不到就留空——空闲时只播动作、不套任何表情，
绝不按序号取「第一个可用表情」：Natori 的表情表第一项是 `Angry`，
按序号兜底会让没写清单的 Natori 永远挂着一张生气的脸。
写一份 `pet.json` 把 `normal` 指对即可。

## 已知限制

这些是开发期间实测确认的事实，不是待办事项。

- **桌宠窗口仍然是整块矩形，但透明处不吃点击。** 窗口本身是**整块透明矩形**
  （缩放为 1 时是 300×560，放大后按比例变大），Windows 没有逐像素命中测试，
  所以可点击区域是**按渲染结果算出来的**：渲染层量出形象真正不透明的那一块，
  光标落在形象外的留白上时，窗口就临时变成「不吃鼠标事件」
  （点击落到桌面上，桌宠仍跟着光标转头）。
  形象上的点击、拖拽、面板弹出都不受影响。
  留在画面上的那一小块透明区域**仍然盖不住下面的窗口**——
  视觉上它本来就是空的，只是鼠标不再被它吃掉。
  设置窗口里的「**鼠标穿透**」是另一回事：那个是**整个窗口**都不吃点击
  （连角色本身也点不到），需要时再开。
- **桌宠放大到屏幕放不下为止。** 窗口尺寸跟着缩放走（基准视口 300×560 乘以缩放），
  但不会超过所在显示器的可见工作区：再大，角色的头就要跑到屏幕外面去了。
  所以在小屏幕上，滑块拖到底也未必达到 2.0 倍的实际尺寸。
  夹紧按**形象**算（窗口可以有一部分在屏幕外，那部分是透明留白），
  但角色本身始终完整留在屏幕内。
- **混合 DPI 跨显示器拖拽会有一次跳变。** 拖拽增量是把「渲染层的
  `window.screenX`」与「指针事件的 clientX」拼起来算的，而前者是 DIP 单位；
  角色一旦被拖到缩放比例不同的显示器上，这段拖拽的增量会在两套比例之间混用，
  产生一次跳变，并让该次拖拽余下部分的移动速率有偏差。
  两套坐标一旦对不上（跨缩放比例、或者窗口刚被移动过还没同步），
  增量会离谱到把角色直接甩到屏幕角落。
  单个 100 % 缩放的显示器上行为是精确的。
- **模型加载失败后的回退目标是注册表的第一项。** 若第一项**就是**那个坏掉的形象，
  回退等于没回退：桌宠仍然是空的。此时可以在设置窗口里把这个形象**移除**
  （预制形象的「删除」就是从列表里去掉它），或者删掉对应的模型目录后
  重跑 `npm run setup`。
  错误弹窗里写明了这一点。更聪明的做法是「依次试下一个能加载的形象」，
  但那是一次行为变更，超出当前范围。
- **`app://` 提供的是整个项目目录，不只是资源包。** 渲染层因此可以读到项目根目录下的
  文件（例如 `app://bundle/package.json`）。以 `.` 开头的路径段会被拒绝，
  目录穿越到项目根之外也会被拦下；另外有一份**拒绝清单**挡住密钥类文件
  （`minimax-api-key`、`*.key`、`*.pem` 等），渲染层读不到它们。
  渲染层实际只加载自己的模块和模型资源，没有不受信任的代码在其中运行。
  另有一个**虚拟根** `/__models__`，映射到用户数据目录里的导入模型
  （`<userData>/live2d/models/`）——它同样受越界检查约束，
  只能提供那个目录里的东西。
- **Cubism 2 老模型没有口型同步。** 语音播报时嘴不会跟着动。
  `pixi-live2d-display` 的 Cubism 2 运行时没有提供口型参数列表，
  口型驱动拿不到参数就整个静默关闭了（不报错，也不影响其它功能）。
- **气泡不接收点击。** Windows 没有逐像素命中测试，整个窗口矩形都是热区——
  所以气泡始终是点击穿透的（输入框那种形态已经下线，输入统一在插件面板里）。- **插件面板会盖住一小块桌面。** 它是常驻置顶的浮窗，摆在桌宠旁边；
  点它外面就会收起。卡片四周留着一圈透明边距（那是给投影画的），
  那圈边距也会吃掉落在上面的点击——Windows 没有逐像素命中测试。
- **插件只有「本地目录」这一条路。** 商店（在线安装）还没做：
  插件要么在 `plugins/` 里（随程序分发），要么在 `userData/plugins/` 里（自己放）。
- **语音播报依赖外部接口。** 走 MiniMax TTS，需要联网与有效的 API Key；
  没配或合成失败时**静默降级**成纯文字气泡（终端里留一行日志）。
  音色 id 由 MiniMax 侧决定，随时可能变——设置里可以自由输入新的 id。
- **模型自带的声音只在「点桌宠」时被静音。** 别的动作（待机、拖拽）
  里带的 wav 照旧响——静音是**这一次动作**的事，不是全局开关。
- **台词的语音是事先合成的，改完设置要等一会儿。** 改了音色或台词之后，
  新的语音在后台生成（每句一次接口调用）。在那之前点它，
  那一句会现场合成一次（要等几百毫秒）。
- **模型自带的声音在随机池里只占一项。** 抽签决定的是「用不用模型的声音」，
  用哪个 wav 还是清单定的那个（摸头是 TapBody 的第 0 个、点身体是第 1 个）——
  Haru 的 TapBody 有 4 个带声音的动作，但它们不各自参与抽签。
- **没有电量百分比。** Electron 45 的 `powerMonitor` 没有这个 API，
  系统状态里给的是「在电池上/已接电」与温度状态。
- **剪贴板助手默认关闭，且只在内存里留内容。** 它靠每 2 秒轮询发现变化，
  所以「复制完立刻切走」这种场景可能捕捉不到。
- **`npm audit` 会报 2 条 critical**（另有 3 条 moderate）。critical 都来自 `gh-pages`——它是
  `pixi-live2d-display@0.4.0` 的传递依赖（那个包把发布文档的工具链错当成了运行时依赖）。
  它只在开发期使用，运行时不会被加载。**故意不修**：`npm audit fix --force` 会把
  `pixi-live2d-display` 降到 `0.3.1`，那样就不再支持 Cubism 4（`.moc3`）模型。
- **`window.__pet.setIdleMs(ms)` 是测试缝**，用来缩短空闲动画间隔以便测试；
  渲染层里任何脚本都能调用它。`window.__pet.switchModel(id)` 同理：
  它是诊断钩子，直接挂载模型，绕过持久化、主进程与形象 id 解析规则。
  正常使用请走设置窗口。诊断面上还有 `mood` / `emotion` / `speechCount` /
  `mouthAmplitude` 等只读字段，供自动化断言用。
  轮廓相关的诊断面有三个：`contentRect`（形象在窗口里的可见矩形）、
  `silhouetteReady`（轮廓量出来没有）、`isOnFigure(x, y)`（这个点在不在形象上）。
- **聊天要花钱、要联网、还依赖模型名。** 它走外部大模型接口，
  默认**关闭**。开了之后：没有 Key 就会每次都失败；模型名填错会返回
  「该模型未开通」——它和「模型名不存在」是同一个错码，看起来一模一样。
  桌宠把说过的话记在 `assistant.json` 里（短期记忆与长期事实），
  设置页里可以逐条查看并一键清空。
- **主动搭话默认关着。** 开了它会按间隔主动开口，每次都要调一次接口；
  护栏（深夜不打扰、用户刚说过话不插嘴、失败指数退避）只挡住了大部分
  不合时宜的情况，剩下的要靠设置里的间隔自行把握。
- ⚠️ **真正的系统级按键无法自动化验证**：E2E 不写注册表、不真的注册全局快捷键
  （会污染测试机），这两项只能人工验证。
  写注册表会污染跑测试的机器，而且注册表项可能指向临时路径，清理不掉；
  按全局键会抢走别的软件的键，测试机上正在跑的东西会中招。
  E2E 把注册下来的**回调**记下来，测试可以「按一下」它——
  所以「按下 → 输入框被唤醒、焦点落在框里」这条链是自动化的，
  而「这个组合在系统里真的按得出来」仍然要人工验证，
  见下面的「人工验证清单」。
- ⚠️ **停靠状态不支持每屏独立配置**：停靠边是一个全局值。
- ⚠️ **穿透与停靠同时打开时，桌宠既点不到也只露一条边。**
  唯一的召回方式是全局快捷键，或托盘菜单里的「取回桌宠」——
  这两个开关各自单用都没问题，叠在一起就会把桌宠困住。
- ⚠️ **磁吸阈值（24px）与停靠阈值（8px）叠出来的观感**：
  桌宠离边缘很近、又被朝那边推的时候，一次轻推（10px 左右）
  就可能让它贴齐**并**藏起来——看着像「手滑了一下，桌宠就没了」。
- ⚠️ **停靠后往回拖会「慢半拍」**：被边缘吃掉的增量会留在累加器里，
  窗口继续钉在边缘、与光标同步。这是拖拽的老行为，不是贴边停靠新引入的。
- ⚠️ **语音原先不受音量控制**：改动前是提示音有音量、桌宠说话没有，
  本次把语音接进了主增益——但依赖第三方 TTS 返回的音频本身。
- **`DESK_PET_TTS_HOSTS` 可以改掉语音接口的域名。** 它是测试与开发用的覆盖口
  （E2E 靠它把请求指向本地桩服务），生产环境不需要设。

## 人工验证清单

下面这几项**自动化测不了**（原因见「已知限制」），需要手动走一遍：

1. **开机自启**：在设置里勾上「开机自启」→ 打开「任务管理器 → 启动」→
   确认有本应用 → 注销重登 → 桌宠自动出现。
2. **快捷键**：在设置里点「重新录制」→ 按 `Ctrl+Alt+K` → 显示「已生效」→
   最小化所有窗口 → 按 `Ctrl+Alt+K` → 桌宠出现/消失。
3. **快捷键冲突**：录制一个已被别的程序占用的组合（如 `Ctrl+Alt+Delete`）→
   提示「已被其他程序占用」，且原来的组合仍然能用。
4. **穿透 + 停靠同时开**：两个开关都打开 → 桌宠既点不到也只露一条边 →
   用快捷键唤回 → 桌宠完整出现。
5. **输入框快捷键**：在设置里点「录制」→ 按 `Ctrl+Alt+Space` → 显示「已生效」→
   点一下别处让桌宠失焦 → 按 `Ctrl+Alt+Space` → 搜索框出现，
   焦点已经在框里，可以直接打字。
   再点「清除」→ 按同一个组合 → 什么也不发生。
6. **透明处不吃点击 + 拖到屏幕顶**：把鼠标移到角色**上方那片透明留白**上 →
   点一下 → 桌面上的东西被点到（不是弹输入框）；移到角色身上再点 →
   输入框弹出来。再把角色**一直往上拖** → 角色的头顶贴到屏幕顶，
   窗口的上半截（透明的那截）跑到屏幕外——这是按形象算的结果。
   （E2E 只能验证到渲染层的判定：Windows 层面的「点击落到桌面上」
   要靠真鼠标，所以这一条留在这里手验。）
