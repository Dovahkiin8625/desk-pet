# 视频形象制作说明

桌宠支持**基于一组视频的形象渲染**：把角色的各个动作做成视频，配一份
`avatar.json` 清单，导入后桌宠就会按配置播放。与 Live2D / Spine 是并列的第三种形象类型。
要看视频怎么生成的，先看 [`docs/i2v-prompts.md`](../i2v-prompts.md)（I2V 变体提示词，
决定视频里有哪些动作）。

内置预制形象 **miya** 就是这么做出来的（`assets/models/miya/`），
缺的视频后续会补——见文末「给 miya 补视频」。

## 一、快速开始（用自己的视频做一个形象）

1. 准备一个目录，里面放视频文件和一份清单：

   ```text
   我的形象/
     avatar.json          ← 清单（配置）
     videos/idle.webm     ← 视频（相对路径由清单引用）
     videos/laugh.webm
     ……
   ```

2. 设置窗口里点「导入模型…」，选中这个目录即可。
   导入时会校验清单与视频文件；缺失的条目会被跳过并提示，**有一条可用视频就能成功**。
3. 切到这个形象，桌宠就开始播待机视频；
   右键「动作」菜单里能看到清单里的每个动作（按 label 显示）。

## 二、准备视频（I2V 绿幕 → 透明 WebM）

I2V 生成的视频是**绿幕 mp4**，桌宠直接显示会带着一块绿板。
输入必须是**抠好的透明 WebM（VP9 + alpha）**。用 ffmpeg 转一次：

```bash
ffmpeg -i 输入.mp4 \
  -vf "chromakey=0x0E8C4B:0.11:0.06,despill=green,format=yuva420p" \
  -c:v libvpx-vp9 -crf 34 -b:v 0 -c:a libopus -b:a 48k \
  输出.webm
```

参数说明：

- `0x0E8C4B` 是**示例**里的绿幕颜色（实测 miya 样例为 RGB ≈ (14, 140, 75)）。
  不同模型的输出可能不同，先取样四角的颜色换掉它（ffprobe/截图工具都行）。
- `similarity`（0.11）：进入抠像范围的颜色距离。**不能贪大**——I2V 的皮肤
  是浅色肤色（比如 (248, 220, 199)），chroma 上离绿幕很近，similarity 超过 ~0.13
  胸口等阴影肤色就会被一起抠掉，角色会「只剩阴影」。
  建议先用 `0.10~0.12`，再抽 2~3 帧量 alpha 分布（背景要 <32、角色要 >223）验收。
  注意 ffmpeg 自己**读不出** webm 的 alpha（见下），不能靠 ffprobe 判断成败。
- `blend`（0.06）：边缘羽化，避免硬边锯齿。
- `despill=green`：抑制人物边缘的绿色溢色（绿边）。
- 建议 `-crf 34`：I2V 画面是平滑插画风，34 左右体积与画质比较平衡。
- 视频里**自带音轨**（AAC）会被转成 Opus 保留下来，但桌宠默认**静音播放**；
  想听原声的条目，在 avatar.json 里单独写 `"sound": true`。

已知注意点：

- ffmpeg 自己的解码器**读不出 webm 的 alpha**（ffprobe 显示 `yuv420p` 是正常现象）。
  以 Chromium 实际播放为准；桌宠用的是 Electron，与 Chrome 一致。
- 直接从别的抠像工具得到的透明 VP9 WebM 也可以用，不必经过上面的 chromakey。
- 生气1 那种自带白色速度线的画面：速度线不是绿幕，抠不掉——属于预期，接受即可。

视频规格（与 i2v-prompts.md 一致）：**9:16（如 480×864）、24fps、124 帧 ≈ 5.17 秒**。
尺寸不硬性校验，但形象适配按 300×560 窗口算，比例不一致会缩放/截边。

## 三、avatar.json 清单

完整字段：

| 字段 | 说明 |
|---|---|
| `type` | 固定为 `"video"` |
| `idleStrategy` | 多条 `idle` 时的播放策略：`"random"`（缺省，随机）/ `"sequence"`（按清单顺序轮询）。仅一条 idle 时无意义 |
| `id` / `name` | 标识与显示名（导入时 id 以注册表为准，目录名 slug 后去重） |
| `viewport` | 桌宠窗口尺寸的对照值，`300×560`，改它不会改变窗口大小 |
| `fit` | 适配：`scale`（基础缩放，还会乘用户缩放）、`anchor`（默认 `[0.5, 1.0]` 贴底居中）、`offset` |
| `videos[]` | **核心**：每个动作一条 |

`videos[]` 每条：

| 字段 | 说明 |
|---|---|
| `key` | 动作标识：唯一；既是右键「动作」菜单里的 group 名，也是 `motion()` 的参数。字母、数字、中横线 |
| `file` | 相对模型目录的路径（`videos/xxx.webm`）。**缺失写 `null`**：导入时会被剔除并提示 |
| `label` | 菜单显示名（缺省用 `key`） |
| `loop` | `true` = 循环播放（待机类）；一次性动作播完自动回到待机池 |
| `sound` | `true` = 播放原声；**缺省静音** |
| `semantic` | 语义绑定：交互键 `idle` / `tapHead` / `tapBody` / `drag`，情绪键 `happy` / `smile` / `shy` / `surprised` / `sad` / `angry` / `tired` / `normal`；缺省 = 仅进菜单。**idle 可绑多条**（待机池），其余键只绑第一个 |

语义键与交互的接线：

| 语义键 | 应用行为 |
|---|---|
| `idle` | 待机。绑一条时循环播放；**绑多条时组成「待机池」**：每条从头播，播完按 `idleStrategy` 随机/按序换下一条（此模式下 `loop` 失效）；miya 预制把「默认站立1/2」都绑在这里 |
| `tapHead` | 摸头（点中头部，命中区由几何判定：可见范围上 35% 算头） |
| `tapBody` | 点身体（其余部分）。注意：点身体时若 `smile` 也有绑定，**smile 优先**（表情先于动作，与 Live2D 一致）；想要的条目放右键菜单 |
| `drag` | 开始拖拽时 |
| `smile` | 点身体时的表情（优先于 tapBody） |
| `happy` …`tired`、`normal` | 情绪事件：待办完成（happy）、被拖拽（surprised）、长时间没人理（sad/tired）、**连续猛点 2 秒 3 次（angry）**等。视频形象没有脸，这些地方改为播放绑定该语义的 clip |

情绪事件举例：`SPAM`（连点猛）→ `angry`；待办完成 → `happy`；拖拽 → `surprised` / `neutral`；
长时间没人理 → `sad` / `tired`；被夸奖 → `shy`。具体对应见 `src/renderer/pet/emotion.js`
的 `RULES` 与 `EMOTION_EXPRESSION`。

- 语义键同一个只绑一个，重复的条目退回「仅菜单」（不会报错）。`idle` 例外：可绑多条。
- 没有绑定的动作全部进右键「动作」菜单，应用本身不触发。
- 一次性动作播完**自动切回待机池**（或所选的循环待机）。
- 写了应用不认的 `semantic`：该条目退回菜单可见，不会报错。

缺失视频的行为：

- `file: null` 或文件不存在 → 导入时警告并跳过该条，其余照常导入；
- 整个形象一条可用视频都没有 → **导入失败**并提示原因；
- 路径越界（如 `../xxx.webm`）→ 该条被拒绝。

## 四、配置模板

`docs/开发说明/视频形象-avatar-template.json` 是一份填好坑位的模板：
20 种变体类型（与 i2v-prompts.md 一一对应），每个 `file` 先填 `null`，
补视频时改成实际路径、补上 label 即可用。最小可用的形象只需要 `idle` 一条：

```jsonc
{
  "type": "video",
  "videos": [
    { "key": "idle", "file": "videos/idle.webm", "label": "待机", "loop": true, "semantic": "idle" }
  ]
}
```

## 五、给 miya 补视频（开发者）

1. 按「二」把新视频转成透明 WebM，放进 `assets/models/miya/videos/`；
2. 在 `avatar.json` 里把对应条目的 `file: null` 改成 `videos/新视频.webm`，
   需要绑交互的语义就加 `semantic`（miya 目前把「默认站立1/2」都绑了 `idle`，
   随机轮播；`"idleStrategy": "random"` 写在 avatar.json 顶层）；
3. 与 `avatar.json` 一起提交（`.gitignore` 里已为 miya 的 videos 目录开了例外）。

当前 miya 已有：待机×2（随机轮播）、大笑、比心×2（`smile` / `tapBody`）、生气×2（`angry`）、
跳舞×2、特殊动作×2；缺的视频按上面补齐即可。

## 六、常见问题

- **导入后桌宠不动 / 只有一张没画出来的图**：检查 `avatar.json` 的 `videos[].file`
  指向的文件真实存在；至少要有一条可用。报错会逐条说明哪条不可用。
- **皮肤不见了 / 只剩阴影**：`similarity` 开太大，浅色皮肤被抠进背景了。
  按上面的方法把 similarity 降到 0.10~0.12 重新转码再导入。
- **绿幕没抠干净 / 边缘绿色**：跟 similarity 反着来——加大 similarity 或换
  `colorkey`；绿边明显就开 `despill=green`（见「二」）。
- **角色边缘有绿色阴影**：i2v 生成常带绿溢色，提高 despill 参数，
  或在 i2v 提示词里把绿幕背景写成纯色再生成。
- **想让某条动作播原声**：该条加 `"sound": true`。
- **桌宠一直不会「比心」之类的**：那些条目默认只在右键菜单里；
  想绑摸头/点身体，把它改成 `semantic: "tapHead"` / `"tapBody"`。
- **轮廓/点击区域不准**：轮廓是按渲染结果的 alpha 量出来的（含待机动画的微小变化，
  每 3 秒刷新一次）；透明 WebM 做出来多半没问题，是绿幕/白底视频才会整体偏大。
