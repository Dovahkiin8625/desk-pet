## 1. 三十秒上手

一个插件 = `plugins/<id>/` 一个目录，里面两个文件：

```
plugins/my-plugin/
  plugin.json
  main.js
```

`plugin.json`：

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "icon": "🎯",
  "description": "一句话说明",
  "keywords": ["mine", "wode", "我的"]
}
```

`main.js`：

```js
export default function createMyPlugin() {
  const page = (ctx) =>
    ctx.ui.makePage({
      pluginId: 'my-plugin',
      title: '我的插件',
      blocks: [ctx.ui.textBlock('你好')],
    });

  return {
    page,
    action(ctx, actionId, value) {
      return { ...page(ctx), status: `收到动作 ${actionId}` };
    },
  };
}
```

**就这样。** 没有注册表，没有构建步骤，不用改宿主。把目录放进 `plugins/` 重启应用，它就出现在面板的搜索里了。

用户自己的插件放 `<userData>/plugins/<id>/`，结构完全一样；**同名时用户的那个算数**。

> **目录名必须等于清单里的 `id`。** 不等的话这个插件被跳过，只在日志里留一行。

## 2. 清单 plugin.json

只有一份定义：`src/shared/plugin.js`。宿主观校验，你照着写。

### 顶层字段

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `id` | **是** | — | 只能用小写字母、数字、连字符（`/^[a-z0-9][a-z0-9-]{0,63}$/`）。**必须等于目录名** |
| `name` | **是** | — | 面板上显示的名字 |
| `icon` | 否 | `'•'` | 就是一个字符串，当文本渲染 |
| `description` | 否 | `''` | 一句话说明 |
| `keywords` | 否 | `[]` | 搜索词。实践中中英文与拼音都放进去（`["录屏", "luping", "screen"]`） |
| `entry` | 否 | `'main.js'` | 入口模块。**相对路径，不能越出插件目录** |
| `window` | 否 | `null` | 独立窗口规格，见下 |
| `widget` | 否 | `null` | 桌面小部件规格，见下 |

`entry` 与 `page` 都会被拼到插件目录后面去拼路径——一个 `../../` 就能跑到插件目录外面，
那是**任意文件**读取与执行。所以路径必须留在插件目录里（`isSafeRelativePath`）。

### `window` / `widget` 段

| 字段 | 默认 | 范围 |
|---|---|---|
| `page` | `''` | 相对路径，指向插件自己的 HTML |
| `title` | `''` | 窗口标题 |
| `width` | `360` | 夹在 `[200, 1200]` |
| `height` | `420` | 夹在 `[120, 900]` |
| `refreshMs` | `0` | `0` = 不刷新；`>0` 夹在 `[500, 3600000]`（写 1 会被夹到 500，太密的轮询会把 CPU 跑满） |
| `alwaysOnTop` | `true`（写了该段时） | 独立窗口由用户用 📌 切换；小部件永远置顶 |

**没写 `window` 段不代表不能开独立窗口。** 「在新窗口打开」是桌宠给**所有**插件的能力，
宿主会合成一份默认规格（标题 = 插件名，360×420，`alwaysOnTop: false`，不刷新）。

**`widget` 段没有就是没有。** 小部件要占着用户的桌面，由插件自己决定要不要。

## 3. 插件实例：你要导出的东西

`main.js` 导出**一个默认工厂函数**。宿主在加载时调用它**一次**，拿到一个实例对象。

```js
export default function createMyPlugin(ctx) {
  return {
    // ……
  };
}
```

实例上的方法**全都是可选的**——没写宿主就跳过，不会报错。

| 方法 | 什么时候被调 | 返回 | 干什么 |
|---|---|---|---|
| `page(ctx)` | 面板要显示你的时候 | `Page` 或 `Promise<Page>`，**`null` 表示「关掉面板」** | 声明式界面的内容 |
| `action(ctx, actionId, value)` | 用户在积木界面上动了 | 新的 `Page`（`null` = 关掉面板） | 处理动作 |
| `meta(ctx)` | 只在插件**有自己的页面**时被调 | `{title?, subtitle?, status?}` | 标题那几个字段 |
| `data(ctx)` | 自带页面打开时 | 任意数据 | 首份数据 |
| `tick(ctx)` | 按 `refreshMs` 周期 | 任意数据 | 周期数据 |
| `act(ctx, actionId, payload)` | 自带页面里用户动了 | 任意数据 | 处理动作 |

**注意 `meta` 与 `page` 的分工：** 插件有自己的页面时，界面是插件自己画的，宿主**不重画**——
它只取 `meta()` 给的标题那几个字段。所以带页面时，`meta()` 要写得**便宜**（别在里面去列系统窗口，
那一下要几百毫秒）。没写 `meta()` 就退回用 `page()` 给的那几个。

## 4. ctx：宿主给你的上下文

工厂函数和每个方法都会收到一个 `ctx`：

```js
{
  plugin: { id, manifest, dir, source },
  assistant,        // 助理总控（见下）
  openSettings,    // 打开设置窗口
  update,          // (page) => void，异步动作完成后再刷新一次面板
  ui,              // 界面积木
  host,            // 宿主能力
}
```

### `ctx.ui` —— 界面积木

`makePage` / `textBlock` / `listBlock` / `inputBlock` / `buttonsBlock` / `toggleBlock` /
`emptyBlock` / `messagesBlock`。用法见第 5 节。

### `ctx.assistant` —— 助理总控

待办、提醒、番茄钟、天气、剪贴板、系统状态的读写都在它那儿。

```js
// 读
assistant.todosView()        assistant.remindersView()   assistant.pomodoroView()
assistant.weatherView()      assistant.statusView()      assistant.clipboardView()
assistant.readClipboard()    // async（Electron 45 的 clipboard.readText 返回 Promise）
assistant.chatHistoryView()

// 改
assistant.addTodo(text)      assistant.toggleTodo(id)     assistant.clearDoneTodos()
assistant.addReminder(...)   assistant.removeReminder(id)
assistant.startPomodoro()    assistant.pausePomodoro()   assistant.resumePomodoro()
assistant.resetPomodoro()
assistant.setWeatherCity(city)  assistant.setWeatherEnabled(b)
assistant.setHotAlertEnabled(b) assistant.setClipboardEnabled(b)

// 对话
assistant.say(text)          assistant.chat(text)        assistant.clearChatHistory()
```

这些**都不弹气泡**——面板开着的时候气泡横在上面会挡住内容。

### `ctx.host` —— 宿主能力

```js
host.listAll()                    // 全部插件 + 启用状态
host.setEnabled(id, enabled)      // 开/关一个插件
host.isEnabled(id)                // 这个插件开着吗
host.openWindow(id, mode)         // 'window' | 'widget'
host.closeWindow(id)
// 你的界面开合了（第一个界面挂上 / 最后一个摘掉）
// 返回取消订阅的函数
host.onSurfaceChange((pluginId, open) => { … })
```

`onSurfaceChange` 适合做「只在界面开着时才生效」的东西——录屏的快捷键就是这么做的：
工作台关了就注销快捷键，别去抢别的程序的组合键。

## 5. 界面（一）：声明式积木

**这是最简单的路线**：你返回一个页面，宿主画。适合表单、列表、开关这类界面。

### 页面长什么样

```js
ctx.ui.makePage({
  pluginId: 'my-plugin',
  title: '标题',
  subtitle: '副标题',
  status: '底部那行提示',
  blocks: [ … ],
})
```

### 七种积木

```js
ctx.ui.textBlock('一段文字')

ctx.ui.listBlock([
  { id: 'a', label: '第一项', done: false, hint: '右侧小字',
    actionId: 'pick',   // 点条目本身做什么（默认 = id）
    removeId: 'rm', },  // 条目右边的「×」做什么（空串 = 没有这个按钮）
])

ctx.ui.inputBlock('add', '要做什么？', '添加')
//          id      placeholder  提交按钮的文案

ctx.ui.buttonsBlock([
  { id: 'start', label: '开始', primary: true },
])

ctx.ui.toggleBlock('enabled', '剪贴板助手', true)
//            id          文案           初始状态

ctx.ui.emptyBlock('剪贴板是空的')

ctx.ui.messagesBlock([
  { role: 'user', text: '你好', at: 1712345678901 },
  { role: 'assistant', text: '在呢', at: 1712345678902 },
])
```

`messagesBlock` 与 `listBlock` 的区别：这一块**不可点**（聊天记录不是菜单），每条还带角色与时间。

### 动作的 value 长什么样（重要）

用户在界面上动了什么，会以 `(actionId, value)` 回到 `action(ctx, actionId, value)`。

| 积木 | `actionId` | `value` |
|---|---|---|
| `list` 点条目 | `item.actionId \|\| item.id` | 条目的 `id` |
| `list` 点 ✕ | `item.removeId` | 条目的 `id` |
| `input` 回车/提交 | `block.id` | 输入框里的**字符串** |
| `buttons` 点按钮 | `item.id` | `''`（空串） |
| `toggle` 切换 | `block.id` | **`'true'` / `'false'`（字符串！）** |

`toggle` 回传的是字符串不是布尔——`value === 'true'` 这样比。

### 异步动作完成后刷新

有些动作要等（联网、读盘）。动作返回的页面是**动作发生时**算出来的，
等结果到了要再刷一次：

```js
async action(ctx, actionId, value) {
  if (actionId === 'refresh') {
    const result = await fetchWeather(city);
    ctx.update({ ...ctx.ui.makePage({ …, status: result.ok ? '已更新' : '失败' }) });
    return null;   // 返回 null = 不发新页面（等 update 那次）
  }
}
```

`ctx.update(page)` 只在**面板**里有效——独立窗口里推的是 `tick()` 的数据。

## 6. 界面（二）：自己的页面

积木画不了的东西（图表、复杂布局、实时预览）就自己写 HTML。

### 怎么接上

1. 清单里写 `"window": { "page": "page.html", … }`
2. `page.html` 里：

```html
<link rel="stylesheet" href="/src/renderer/ui/theme.css" />
<script type="module">
  import { bindSurface } from '/src/renderer/ui/pluginPage.js';

  const surface = bindSurface();
  surface.onTick((data) => render(data));
  surface.act('start', { id: 1 });
  surface.setStatus('工作中');
</script>
```

**同一份页面两处用**：面板工作台里宿主把它装进一个 `<iframe>`，独立窗口里也是 `<iframe>`
（窗口的标题栏是宿主的）。所以窄的时候（面板）和宽的时候（用户拉宽的窗口）
怎么排，由**你的页面自己**决定——宿主给内容区套了一层容器，用 CSS 容器查询：

```css
.surface { container-type: inline-size; container-name: surface; }

@container surface (min-width: 520px) {
  .targets { display: grid; grid-template-columns: 1fr 1fr; }
}
```

### `bindSurface()` 给你的东西

```js
{
  id,                          // 你的插件 id（从 URL 查询参数读的）
  mode,                        // 'window' | 'widget'
  data(),                      // Promise，首份数据
  onData(cb),                  // cb(data)，首份数据到了
  onTick(cb),                  // cb(data)，周期数据到了
  act(actionId, payload),      // Promise，页面里的动作
  action(actionId, value),     // Promise，声明式页面的动作
  setStatus(text),             // 底部那行字
  setHeight(px),               // 报内容高度（只对面板有意义）
}
```

`action()` **一定返回 Promise**——面板那边的通道将来用 invoke，但万一某个通道是 send（没有回执），
页面那边 `.then()` 会炸。所以它被包成了 `Promise.resolve(...)`。

### 页面加载不出来怎么办

路径写错、文件被删——宿主会**自动退回积木界面**，插件照样能用，**不会白屏**。
所以 `page(ctx)` 还是要写（退回时靠它画界面）。

### 设计系统

所有插件界面共用 `src/renderer/ui/theme.css`——颜色、圆角、间距、按钮都在那份文件里。
你的页面链上它，看起来就跟别的插件是同一个产品做的。

## 7. 窗口与小部件

插件界面默认待在**面板**里。面板上永远有 **↗**（在新窗口打开）；
清单里写了 `widget` 段还会多一个 **▣**（变成桌面小部件）。

- **独立窗口**：自己的窗口，能调整大小、能拖到别处；标题栏上有 📌 置顶开关。
- **桌面小部件**：无边框、透明、常驻桌面，整块可以拖。

两者是**同一个窗口的两种样子**，可以来回切（切的时候会重建窗口）。
小部件永远置顶；独立窗口的置顶由用户决定。

### 小部件不一样的地方

小部件的页面是**原样加载**的（自带 preload，不走壳、不走 iframe），
所以 `window.plugin` 就在页面自己身上——直接用裸 API 就行：

```js
window.plugin.onTick((data) => { /* 周期数据到了 */ });
window.plugin.data().then((data) => { /* 首份数据 */ });
window.plugin.act('click', { id: 1 });
window.plugin.window.setAlwaysOnTop(true);
window.plugin.window.setMode('window');   // 切回独立窗口
window.plugin.window.close();
```

**小部件收到的是裸数据**，不是 `{pluginId, data}` 信封——宿主推给小部件时已经把信封拆了。

（`bindSurface()` 在小部件里其实也能用：它先看自己身上的 `window.plugin`，找得到就用。
但既然裸 API 就在手边，没必要绕一层。真正要注意的是**数据的形状不一样**：
小部件那侧拿到的就是插件自己的数据，没有信封。）

**同一个插件如果既有 `window` 段页面又有 `widget` 段页面，就是两套 API、两套心智模型。**
能用一种就别用两种。

### 一个插件只能有一个窗口

宿主的窗口控制器是「一个插件一个窗口」，`window` 与 `widget` 互斥。
需要**同时开好几个窗口**（录屏的捕获页、选区遮罩、控制条、工作台要一起开着），
就得自己 `new BrowserWindow()`——这时要自己写窗口管理与 preload。
`plugins/screen-recorder/lib/windows.js` 是一个完整的例子（也顺便看看它踩了哪些坑）。

## 8. 数据流：谁推给谁

```
                     ┌──────────────── 面板工作台（一个 surface）
   宿主 ──broadcast──▶ │
        ──broadcast──▶ └──────────────── 独立窗口（一个 surface）
```

- 宿主推给界面的东西**一律包成 `{pluginId, data}`**。
- 界面 `invoke` 回来的都是**裸值**。
- 一个插件**只有一个 tick 定时器**，不是每个界面一个（面板和窗口同时开着也是一份）。
- `refreshMs: 0` → 不刷新。宿主只在界面的 `refreshMs` 上按周期调 `tick()`。
- 声明式界面的插件没有 `tick()` 时，宿主改成**重算一次页面**再推下去（番茄钟的倒计时靠这个）。

## 9. 测试

### 单元测试（快，不碰 Electron）

照着 `test/unit/plugin-host.test.js` 的写法：

```js
import { mkdtemp, mkdir, writeFile } from 'node:fs/promises';
import { createPluginHost } from '../../src/main/plugins/host.js';

/** 摆一个插件目录。 */
async function makePlugin(root, id, manifest, main) {
  const dir = join(root, 'plugins', id);
  await mkdir(dir, { recursive: true });
  await writeFile(join(dir, 'plugin.json'), JSON.stringify(manifest, null, 2), 'utf8');
  if (main) await writeFile(join(dir, 'main.js'), main, 'utf8');
  return dir;
}

/** 一个假的助理：插件读写状态都走它。 */
function fakeAssistant() {
  return { todosView: () => ({ items: [] }), addTodo: () => ({ ok: true }) };
}

const root = await mkdtemp(join(tmpdir(), 'plugin-'));
await makePlugin(root, 'my-plugin', { id: 'my-plugin', name: '我的' }, mainSource);
const host = createPluginHost({ rootDir: root, userDataDir: root, assistant: fakeAssistant(), openSettings: () => {} });
await host.load();
```

宿主这一层**不碰 Electron**：它只管插件目录与页面描述。窗口那部分
（`src/main/plugins/window.js`）要 Electron，单测里跑不了。

### 端到端测试（慢，起真应用）

照着 `test/e2e/plugin-surface.spec.js`：

```js
const app = await electron.launch({
  args: [ROOT],
  env: { ...process.env, DESK_PET_USER_DATA: USER_DATA, DESK_PET_E2E: '1' },
});
const pet = await app.firstWindow();
await pet.waitForFunction(() => window.__pet?.modelLoaded === true, null, { timeout: 30000 });
```

固件插件直接写在 `<临时 userData>/plugins/<id>/` 下，结构跟真插件一样。
`plugin-surface.spec.js` 里那个 `e2e-page` 固件是个完整的例子（有清单、main.js、page.html）。

> E2E 会**真的开窗口**。

## 10. 常见坑

| 坑 | 怎么避开 |
|---|---|
| 目录名与 `id` 不一致 | 插件被静默跳过，只在日志里留一行。查 `src/main/plugins/loader.js` 的日志 |
| `entry` / `page` 写出了插件目录 | 被拒（`isSafeRelativePath`）。`../../` 能读到任意文件 |
| `toggle` 的动作值当成布尔 | 它是**字符串** `'true'` / `'false'` |
| `meta()` 里干了重活 | 带页面的插件，宿主每次开面板都会调 `meta()`。列系统窗口那种几百毫秒的活别放这儿 |
| `page()` 返回 `null` | 意思是「**关掉面板**」，不是「画个空页面」。想画空界面用 `emptyBlock` |
| 写了 `window.page` 但文件不在磁盘上 | 宿主退回积木界面（**这是好事**，不是白屏）。但那时 `page()` 就是必需的 |
| `win.webContents.id` 在窗口销毁后读 | 会把主进程整个冻住（「点了退出程序却不退」）。**销毁前存下来** |
| 小部件里用 `bindSurface()` | 小部件是原样加载的，用裸 `window.plugin` |
| 独立窗口里用 `window.plugin` | 独立窗口的页面在 iframe 里，用 `bindSurface()` |
| 插件在主进程里改坏了主进程 | **没有沙箱**。插件就是个普通 Node 模块，`import { app } from 'electron'` 随手可用 |

## 11. 宿主源码地图

要改宿主时看这里。**每份定义只有一份**，改的时候记得两边对齐。

| 文件 | 是什么 |
|---|---|
| `src/shared/plugin.js` | **插件清单与窗口规格的唯一契约**。改清单字段先改这里 |
| `src/shared/panel.js` | 界面积木的形状（`makePage` / `textBlock` / …） |
| `src/main/plugins/paths.js` | 插件根目录：内置 = `<项目>/plugins`，用户 = `<userData>/plugins` |
| `src/main/plugins/loader.js` | 发现（扫目录、读清单、校验、去重）与加载（动态 import） |
| `src/main/plugins/host.js` | 注册、造 ctx、生命周期分发（`open`/`action`/`data`/`tick`/`act`/`refresh`）、开关插件、页面 URL 缓存 |
