## 1. 三十秒上手

一个插件 = `plugins/<id>/` 一个目录，里面两个文件：

```
plugins/my-plugin/
  plugin.json
  main.js
```

`plugin.json`：

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "icon": "🎯",
  "description": "一句话说明",
  "keywords": ["mine", "wode", "我的"]
}
```

`main.js`：

```js
export default function createMyPlugin() {
  const page = (ctx) =>
    ctx.ui.makePage({
      pluginId: 'my-plugin',
      title: '我的插件',
      blocks: [ctx.ui.textBlock('你好')],
    });

  return {
    page,
    action(ctx, actionId, value) {
      return { ...page(ctx), status: `收到动作 ${actionId}` };
    },
  };
}
```

**就这样。** 没有注册表，没有构建步骤，不用改宿主。把目录放进 `plugins/` 重启应用，它就出现在面板的搜索里了。

用户自己的插件放 `<userData>/plugins/<id>/`，结构完全一样；**同名时用户的那个算数**。

> **目录名必须等于清单里的 `id`。** 不等的话这个插件被跳过，只在日志里留一行。

想接给 agent 用的话，再加两样东西：

- `skill.md` + 清单里的 `skill` 段：**说明书**（怎么用你这个插件），见第 2 节；
- 清单里的 `tools[]` + 实例的 `tools()`：**工具**（agent 能直接调的能力），见第 2、3 节。

## 2. 清单 plugin.json

只有一份定义：`src/shared/plugin.js`。宿主观校验，你照着写。

### 顶层字段

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `id` | **是** | — | 只能用小写字母、数字、连字符（`/^[a-z0-9][a-z0-9-]{0,63}$/`）。**必须等于目录名** |
| `name` | **是** | — | 面板上显示的名字 |
| `icon` | 否 | `'•'` | 就是一个字符串，当文本渲染 |
| `description` | 否 | `''` | 一句话说明 |
| `keywords` | 否 | `[]` | 搜索词。实践中中英文与拼音都放进去（`["录屏", "luping", "screen"]`） |
| `entry` | 否 | `'main.js'` | 入口模块。**相对路径，不能越出插件目录** |
| `window` | 否 | `null` | 独立窗口规格，见下 |
| `widget` | 否 | `null` | 桌面小部件规格，见下 |
| `tools` | 否 | `[]` | 你给 agent 提供的工具，见下 |
| `skill` | 否 | `null` | 给 agent 的**说明书**（怎么用你这个插件），见下 |
| `settings` | 否 | `[]` | 你自己的配置项（画在插件自己的页面上），见下 |

`entry` 与 `page` 都会被拼到插件目录后面去拼路径——一个 `../../` 就能跑到插件目录外面，
那是**任意文件**读取与执行。所以路径必须留在插件目录里（`isSafeRelativePath`）。

### `window` / `widget` 段

| 字段 | 默认 | 范围 |
|---|---|---|
| `page` | `''` | 相对路径，指向插件自己的 HTML |
| `title` | `''` | 窗口标题 |
| `width` | `720` | 夹在 `[200, 1200]` |
| `height` | `560` | 夹在 `[120, 900]` |
| `refreshMs` | `0` | `0` = 不刷新；`>0` 夹在 `[500, 3600000]`（写 1 会被夹到 500，太密的轮询会把 CPU 跑满） |
| `alwaysOnTop` | `true`（写了该段时） | 独立窗口由用户用 📌 切换；小部件永远置顶 |

**没写 `window` 段不代表不能开独立窗口。** 「在新窗口打开」是桌宠给**所有**插件的能力，
宿主会合成一份默认规格（标题 = 插件名，720×560，`alwaysOnTop: false`，不刷新）。

**这个尺寸只管第一次打开**：用户拖过窗口之后，拖出来的尺寸会被记住，
下次按它开（标题栏的 **⛶** 能恢复成清单里写的尺寸）。

**`widget` 段没有就是没有。** 小部件要占着用户的桌面，由插件自己决定要不要。

### `tools[]` 段：给 agent 提供工具

桌宠内置了一个 agent（助手）。你的插件可以把能力**接给它**：清单里声明工具，
agent 就能在自己的提示词里看见它、调用它。

```json
{
  "id": "weather",
  "name": "天气",
  "tools": [
    {
      "name": "weather.get",
      "label": "查天气",
      "description": "按城市名查当前的天气（温度与天气状况）。",
      "parameters": {
        "type": "object",
        "properties": { "city": { "type": "string", "description": "城市名，例如「北京」" } },
        "required": ["city"]
      },
      "risk": "read"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | **是** | 全局唯一。只能用小写字母、数字与点（`/^[a-z0-9]+(\.[a-z0-9]+)*$/`），建议 `插件名.动作名` |
| `label` | 否 | 给人看的名字；不写就用 `name` |
| `description` | 否 | **给模型看的**——模型靠这句话决定要不要调它，写清楚点 |
| `parameters` | 否 | JSON Schema（OpenAI tools 的格式）。不写就当成「没有参数」 |
| `risk` | 否 | `read` / `write` / `exec`。不写按最严格算（要确认） |

**清单只是声明，真正干活的是实例的 `tools()`**（见第 3 节）——两边必须同名。
对不上的时候这个工具**不注册**，插件本身照常跑（宿主的宽容度跟「目录名 ≠ 清单 id
就被跳过」一样：一个工具的问题不该把整个插件拖垮）。

**风险等级：插件说的不算数。** 声明 `read` 也不自动放行——
插件提供的工具一律按「要确认」算，因为宿主没法验证你的实现到底做了什么。
用户在设置里永久放行过的工具（`allowAlways`）才按你声明的来。

### `skill` 段：给 agent 的说明书

工具的 `description` 只说得清「这个工具干什么」，说不清「这个插件整体该怎么用」：
什么时候该用、用之前要先做什么、几个工具之间是什么顺序。
那些话写进每个工具的描述里，同一个插件的工具一多，提示词就翻倍。

`skill` 就是把这些话收在一处，**按需取用**：

```json
{
  "id": "weather",
  "name": "天气",
  "skill": {
    "name": "weather",
    "description": "查当前天气，以及设置默认城市",
    "file": "skill.md"
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 否 | 技能名。默认用插件 id。只能用小写字母、数字与连字符（`/^[a-z0-9][a-z0-9-]{0,63}$/`），**全局唯一** |
| `description` | 否 | **给模型看的**——系统提示词里只有「名字：说明」这一行。不写就用插件的 `description` |
| `file` | 否 | 正文在插件目录里的哪个 markdown 文件。默认 `skill.md`，**不能越出插件目录** |

**`description` 写**什么时候该用它**，不是「它是什么」——模型只看这一行决定要不要读正文。
「查当前天气」这种功能描述模型已经能从工具名看出来了，写它等于白占位置；
「用户问天气、要不要下雨的时候用它」才告诉模型**该在什么时候**想起这个插件。

**三级渐进式披露：**

1. 系统提示词里只有「名字：说明」——模型据此判断「这个插件可能有用」，看不到正文。
2. 模型觉得要用了，调内置的 `skill.read` 读正文，才知道具体怎么用。
3. 正文里提到的别的文件（参考资料、模板），再 `skill.read` 一次并带上 `path` 取。

模型要用你这个插件的工具之前，会先读 `skill.md`。所以正文里要写清楚**用法与顺序**，不写「这个工具干什么」（那是工具 `description` 的活）。

正文最多 2000 字（超了会截断并留痕）。**技能是说明书，不是数据**——
要列一长串东西的话，那应该做成工具。

插件被关掉时，它的技能也从提示词里消失——不该留着「有个技能叫天气」而模型却读不到。

### `settings[]` 段：插件自己的配置

配置控件画在**插件自己的页面**上（宿主把它追加到你的页面末尾）。
桌宠的【设置】里只有两样东西：这个插件开不开、它接不接给 agent——**没有插件的配置项**。
**宿主不替插件猜它要什么配置**：你声明什么类型，就画什么控件。

```json
{
  "id": "pomodoro",
  "name": "番茄钟",
  "settings": [
    {
      "key": "focusMinutes",
      "label": "专注时长（分钟）",
      "type": "number",
      "default": 25,
      "hint": "用户说「开始专注」而没给时长时，用这个。"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `key` | **是** | 配置项的名字。字母开头，只能有字母、数字与下划线。**插件内唯一** |
| `label` | 否 | 控件上显示的名字。不写就用 `key` |
| `type` | 否 | `text` / `number` / `boolean` / `select`。不写当 `text` |
| `default` | 否 | 默认值。**按类型归一**：`"true"` 当布尔写会变成 `true`，`select` 的默认值必须在自己的 `options` 里 |
| `options` | `select` 必填 | 下拉的候选项（字符串数组） |
| `hint` | 否 | 鼠标悬停时的那句话 |

**改了就存，不用再点保存。** 值存在 `plugins.json` 的 `config` 段里。

**只有声明过的 key 才认。** 别的键写进去也没地方显示，宿主会直接丢掉。

在插件里读配置：

```js
const focus = ctx.config.focusMinutes;      // 当前值（默认值 + 用户改过的）
ctx.host.setConfig({ focusMinutes: 45 });    // 改一个
```

`ctx.config` 是**活的**：每次读都是当前值。工具实现会被缓存，
拿快照的话，用户改完设置插件还在用旧值。

## 3. 插件实例：你要导出的东西

`main.js` 导出**一个默认工厂函数**。宿主在加载时调用它**一次**，拿到一个实例对象。

```js
export default function createMyPlugin(ctx) {
  return {
    // ……
  };
}
```

实例上的方法**全都是可选的**——没写宿主就跳过，不会报错。

| 方法 | 什么时候被调 | 返回 | 干什么 |
|---|---|---|---|
| `page(ctx)` | 面板要显示你的时候 | `Page` 或 `Promise<Page>`，**`null` 表示「关掉面板」** | 声明式界面的内容 |
| `action(ctx, actionId, value)` | 用户在积木界面上动了 | 新的 `Page`（`null` = 关掉面板） | 处理动作 |
| `meta(ctx)` | 只在插件**有自己的页面**时被调 | `{title?, subtitle?, status?}` | 标题那几个字段 |
| `data(ctx)` | 自带页面打开时 | 任意数据 | 首份数据 |
| `tick(ctx)` | 按 `refreshMs` 周期 | 任意数据 | 周期数据 |
| `act(ctx, actionId, payload)` | 自带页面里用户动了 | 任意数据 | 处理动作 |
| `tools(ctx)` | 插件被加载时 | 工具实现数组 | 你给 agent 提供的工具，见下 |

**注意 `meta` 与 `page` 的分工：** 插件有自己的页面时，界面是插件自己画的，宿主**不重画**——
它只取 `meta()` 给的标题那几个字段。所以带页面时，`meta()` 要写得**便宜**（别在里面去列系统窗口，
那一下要几百毫秒）。没写 `meta()` 就退回用 `page()` 给的那几个。

### `tools(ctx)`：你给 agent 提供的工具

清单里的 `tools[]` 是**声明**（给模型看的契约），这里是**实现**（干活的那一口）。
两边的 `name` 必须一模一样，对不上就不注册。

```js
export default function createWeatherPlugin(ctx) {
  return {
    tools() {
      return [
        {
          name: 'weather.get',            // 与清单里的同名
          async run({ city }) {           // 参数按清单的 parameters 走
            const name = String(city || '').trim();
            if (!name) throw new Error('要查哪个城市？给个 city');
            const result = await ctx.assistant.fetchWeather(name);
            if (!result?.ok) throw new Error(result?.message || '查不到天气');
            return {
              text: result.message,       // 给模型看的（会被截断）
              data: { city: name },       // 给界面看的（不进上下文）
            };
          },
        },
      ];
    },
  };
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | **是** | 与清单里的 `name` 一致 |
| `run(args)` | **是** | 干活的那一口。参数就是模型给的那些 |

**返回值**：`{ text, data? }`。`text` 是给模型的摘要（会被截断后进上下文），
`data` 是给界面看的结构化数据（**不进**上下文）。

**出错就抛。** 抛出的错误会喂回模型，模型可以换个参数再试一次；
返回空字符串的话，模型会以为「查到了，就是空的」。

插件被关掉时，它的工具会从 agent 的工具表里消失——模型也就看不见它了。
用户也可以在【设置】的「插件」分区里单独把它从 agent 摘掉（默认是接上的）：
那时插件自己照常能用，只是不给 agent 用。

## 4. ctx：宿主给你的上下文

工厂函数和每个方法都会收到一个 `ctx`：

```js
{
  plugin: { id, manifest, dir, source },
  assistant,        // 助理总控（见下）
  config,           // 你自己的配置值（见下）
  openSettings,    // 打开设置窗口
  update,          // (page) => void，异步动作完成后再刷新一次面板
  ui,              // 界面积木
  host,            // 宿主能力
  agent,           // agent 接口（见下）
}
```

### `ctx.ui` —— 界面积木

`makePage` / `textBlock` / `listBlock` / `inputBlock` / `buttonsBlock` / `toggleBlock` /
`emptyBlock` / `messagesBlock`。用法见第 5 节。

### `ctx.assistant` —— 助理总控

待办、提醒、番茄钟、天气、剪贴板、系统状态的读写都在它那儿。

```js
// 读
assistant.todosView()        assistant.remindersView()   assistant.pomodoroView()
assistant.weatherView()      assistant.statusView()      assistant.clipboardView()
assistant.readClipboard()    // async（Electron 45 的 clipboard.readText 返回 Promise）
assistant.chatHistoryView()

// 改
assistant.addTodo(text)      assistant.toggleTodo(id)     assistant.clearDoneTodos()
assistant.addReminder(...)   assistant.removeReminder(id)
assistant.startPomodoro()    assistant.pausePomodoro()   assistant.resumePomodoro()
assistant.resetPomodoro()
assistant.setWeatherCity(city)  assistant.setWeatherEnabled(b)
assistant.setHotAlertEnabled(b) assistant.setClipboardEnabled(b)

// 对话
assistant.say(text)          assistant.chat(text)        assistant.clearChatHistory()
```

这些**都不弹气泡**——面板开着的时候气泡横在上面会挡住内容。

`startPomodoro(phase, minutes)` 的 `minutes` 不给就用预设（专注 25、休息 5），
给了就按它来——插件的时长设置与 agent 的工具都走这一条路。

### `ctx.config` —— 你自己的配置值

清单的 `settings[]` 声明过的那些 key 的当前值（默认值 + 用户改过的）。

```js
ctx.config.focusMinutes      // 读
```

**它是活的**：每次读都是当前值。工具实现会被缓存，
拿快照的话，用户改完设置插件还在用旧值。

### `ctx.host` —— 宿主能力

```js
host.listAll()                    // 全部插件 + 启用状态
host.setEnabled(id, enabled)      // 开/关一个插件
host.isEnabled(id)                // 这个插件开着吗
host.openWindow(id, mode)         // 'window' | 'widget'
host.closeWindow(id)
host.getConfig()                  // 你自己的配置值（与 ctx.config 一样）
host.setConfig(patch)             // 改你自己的配置值
// 你的界面开合了（第一个界面挂上 / 最后一个摘掉）
// 返回取消订阅的函数
host.onSurfaceChange((pluginId, open) => { … })
```

`onSurfaceChange` 适合做「只在界面开着时才生效」的东西——录屏的快捷键就是这么武装起来的：
用户**打开过一次**录屏之后，快捷键就一直有效（到插件被关掉为止）。
注意别学成「界面一关就注销」：面板失焦会自己收起来，
那样「开始录制」这种快捷键就没有意义了——它的用处正是**不开界面**也能按。

### `ctx.agent` —— 反过来用 agent

你给了 agent 工具，也能反过来让它干活。插件与 agent 跑在**同一个主进程**里，
所以这是直接调用，不走 IPC。

```js
ctx.agent.run(prompt, opts)   // 提交一个后台任务 → { ok, taskId?, message? }
ctx.agent.cancel(taskId)      // 取消一个任务 → { ok, message? }
ctx.agent.history()           // 读聊天记录 → ChatEntry[]
ctx.agent.onEvent(cb)         // 订阅 agent 的动静 → 取消订阅的函数
```

`onEvent` 收到的是**聊天记录条目**（`{ id, kind, text, meta, … }`）：
写一条记录就推一条，插件页面照着画就行。

**后台任务运行时已经上线**：`run()` / `cancel()` 真的能提交与取消任务。
接口没接上时它们会明确回一句「后台任务运行时还没上线」——
**它不假装成功**：给插件一个假成功，插件会以为任务在跑，而它根本没进队列。

看板上要用的几个方法也在 `ctx.agent` 上：

```js
ctx.agent.tasks()             // 列出后台任务 → Task[]
ctx.agent.steer(taskId, note) // 追加一句要求 → { ok, message? }
ctx.agent.archive(taskId)     // 归档一个结束的任务 → { ok, message? }
ctx.agent.approvals()         // 待答的审批 → [{ id, taskId, title, text, risk }]
ctx.agent.answerApproval(id, decision) // 答复一条 → { ok, message? }
```

`tasks()` 里每一项都带 `status`（`queued`/`running`/`waiting_approval`/`done`/`failed`/`cancelled`/`interrupted`）、
`stepIndex`（第几步）、`error`（为什么失败）、`elapsedMs`（跑了多久），
还有 `createdAt`（什么时候来的）、`result`（最终结果）与 `steps`（步骤清单：
每一步的工具名、参数、结果、时刻）。
接口没接上时 `tasks()` 回空数组、`approvals()` 回空数组，
`steer` / `archive` / `answerApproval` 回 `{ ok: false, message: '后台任务运行时还没上线' }`。

**待答的审批是气泡与插件界面共用的同一份队列。**
桌宠气泡上弹的那张「需要你点头」卡，和插件读到的 `ctx.agent.approvals()` 是同一批。
**谁先答谁算数**：另一个口子再答同一条，回 `{ ok: false }` 与一句「这个已经答复过了」，
状态不变。插件要答复就用 `answerApproval(id, 'allow')`——
`decision` 取 `allow` / `deny` / `always` / `cancel`。

`plugins/tasks/` 是个完整例子：它把 `tasks()` 与 `approvals()` 凑成一份快照，
让界面同时显示「在跑的」与「等你点头的」。

### `ctx.push` —— 把数据推给自己的界面

数据变了，界面要跟着变：`ctx.push(data)` 把数据推给插件自己的界面
（面板工作台里的 iframe、独立窗口里的 iframe，都算）。

```js
ctx.push({ entries: [一条记录] })   // 推给自己的界面
```

**推不丢**：界面还没开着时推了也没有地方去，但插件不用管——
界面打开时宿主会先给一份**完整快照**（`data()`），
你自己保证快照与推送说的是同一件事就行。

页面那边一般**合**着收：快照与推送说的是同一件事，页面按 id 去重。
真的要**换**一份整的（比如清空之后），在数据里带上 `replace: true`——
页面先清再合。少了这个标记，推送就只是「多了一条」。

信封是宿主加的：界面落点收到的是 `{ pluginId, data }`，
页面靠 `pluginId` 过滤串台（面板可能在两个插件之间来回切）。

## 5. 界面（一）：声明式积木

**这是最简单的路线**：你返回一个页面，宿主画。适合表单、列表、开关这类界面。

### 页面长什么样

```js
ctx.ui.makePage({
  pluginId: 'my-plugin',
  title: '标题',
  subtitle: '副标题',
  status: '底部那行提示',
  blocks: [ … ],
})
```

### 七种积木

```js
ctx.ui.textBlock('一段文字')

ctx.ui.listBlock([
  { id: 'a', label: '第一项', done: false, hint: '右侧小字',
    actionId: 'pick',   // 点条目本身做什么（默认 = id）
    removeId: 'rm', },  // 条目右边的「×」做什么（空串 = 没有这个按钮）
])

ctx.ui.inputBlock('add', '要做什么？', '添加')
//          id      placeholder  提交按钮的文案

ctx.ui.buttonsBlock([
  { id: 'start', label: '开始', primary: true },
])

ctx.ui.toggleBlock('enabled', '剪贴板助手', true)
//            id          文案           初始状态

ctx.ui.emptyBlock('剪贴板是空的')

ctx.ui.messagesBlock([
  { role: 'user', text: '你好', at: 1712345678901 },
  { role: 'assistant', text: '在呢', at: 1712345678902 },
])
```

`messagesBlock` 与 `listBlock` 的区别：这一块**不可点**（聊天记录不是菜单），每条还带角色与时间。

### 动作的 value 长什么样（重要）

用户在界面上动了什么，会以 `(actionId, value)` 回到 `action(ctx, actionId, value)`。

| 积木 | `actionId` | `value` |
|---|---|---|
| `list` 点条目 | `item.actionId \|\| item.id` | 条目的 `id` |
| `list` 点 ✕ | `item.removeId` | 条目的 `id` |
| `input` 回车/提交 | `block.id` | 输入框里的**字符串** |
| `buttons` 点按钮 | `item.id` | `''`（空串） |
| `toggle` 切换 | `block.id` | **`'true'` / `'false'`（字符串！）** |

`toggle` 回传的是字符串不是布尔——`value === 'true'` 这样比。

### 异步动作完成后刷新

有些动作要等（联网、读盘）。动作返回的页面是**动作发生时**算出来的，
等结果到了要再刷一次：

```js
async action(ctx, actionId, value) {
  if (actionId === 'refresh') {
    const result = await fetchWeather(city);
    ctx.update({ ...ctx.ui.makePage({ …, status: result.ok ? '已更新' : '失败' }) });
    return null;   // 返回 null = 不发新页面（等 update 那次）
  }
}
```

`ctx.update(page)` 只在**面板**里有效——独立窗口里推的是 `tick()` 的数据。

## 6. 界面（二）：自己的页面

积木画不了的东西（图表、复杂布局、实时预览）就自己写 HTML。

### 怎么接上

1. 清单里写 `"window": { "page": "page.html", … }`
2. `page.html` 里：

```html
<link rel="stylesheet" href="/src/renderer/ui/theme.css" />
<script type="module">
  import { bindSurface } from '/src/renderer/ui/pluginPage.js';

  const surface = bindSurface();
  surface.onTick((data) => render(data));
  surface.act('start', { id: 1 });
  surface.setStatus('工作中');
</script>
```

**同一份页面两处用**：面板工作台里宿主把它装进一个 `<iframe>`，独立窗口里也是 `<iframe>`
（窗口的标题栏是宿主的）。所以窄的时候（面板）和宽的时候（用户拉宽的窗口）
怎么排，由**你的页面自己**决定——按**自己的视口宽度**用媒体查询切：

```css
@media (min-width: 560px) {
  .targets { display: grid; grid-template-columns: 1fr 1fr; }
}
```

**不要用容器查询**：容器查询查的是**同一个文档里**的祖先容器，
而你的页面在 iframe 里（另一个文档）——`@container surface (…)` 在这里永远不生效。
（宿主给**它自己画的积木界面**套了 `.surface` 容器，那一套是宿主的事，插件页面用不上。）

### `bindSurface()` 给你的东西

```js
{
  id,                          // 你的插件 id（从 URL 查询参数读的）
  mode,                        // 'window' | 'widget'
  inPanel,                     // 在面板的 iframe 里吗（面板窄、窗口宽）
  data(),                      // Promise，首份数据
  onData(cb),                  // cb(data)，首份数据到了
  onTick(cb),                  // cb(data)，周期数据到了
  act(actionId, payload),      // Promise，页面里的动作
  action(actionId, value),     // Promise，声明式页面的动作
  setStatus(text),             // 底部那行字
  setHeight(px),               // 报内容高度（只对面板有意义）
}
```

`action()` **一定返回 Promise**——面板那边的通道将来用 invoke，但万一某个通道是 send（没有回执），
页面那边 `.then()` 会炸。所以它被包成了 `Promise.resolve(...)`。

`inPanel` 值得留意：两处的高度策略是**相反**的——
面板的窗口按内容撑开（页面报多高，面板就开多高），独立窗口的高度是用户拖出来的（按视口铺满才对）。
页面要是按视口高度铺满，在面板里就会与面板互相卡死（页面报 100vh，面板按 100vh 开，页面又看到 100vh……）。

`setHeight(px)` 要报的是**内容**的高度，不是视口的高度：
`document.documentElement.scrollHeight` 至少是视口那么高，
iframe 比内容高的时候它会多报，面板按多报的高度开窗，窗口就再也缩不回去了。
量 `document.body.getBoundingClientRect().height` 之类才是内容的高度（记得**向上取整**）。

面板的窗口有上限（按屏幕的工作区算），内容比上限还高时：
窗口开到上限，多出来的那一截在 **iframe 内部滚动**——
页面要能滚（`html` 不要 `overflow: hidden`），否则底部就够不着了。

### 页面加载不出来怎么办

路径写错、文件被删——宿主会**自动退回积木界面**，插件照样能用，**不会白屏**。
所以 `page(ctx)` 还是要写（退回时靠它画界面）。

### 设计系统

所有插件界面共用 `src/renderer/ui/theme.css`——颜色、圆角、间距、按钮都在那份文件里。
你的页面链上它，看起来就跟别的插件是同一个产品做的。

## 7. 窗口与小部件

插件界面默认待在**面板**里。面板上永远有 **↗**（在新窗口打开）；
清单里写了 `widget` 段还会多一个 **▣**（变成桌面小部件）。

- **独立窗口**：自己的窗口，能调整大小、能拖到别处；标题栏上有 📌 置顶开关。
  尺寸是清单里 `window.width/height` 写的那个（没写 `window` 段时宿主合成 720×560）；
  用户拖过的尺寸会被记住，下次按它开，标题栏上的 **⛶** 能恢复成清单里的尺寸。
- **桌面小部件**：无边框、透明、常驻桌面，整块可以拖。拖到哪儿就待在哪儿——**不跟桌宠跑**。

两者是**同一个窗口的两种样子**，可以来回切（切的时候会重建窗口）。
小部件永远置顶；独立窗口的置顶由用户决定。

### 小部件不一样的地方

小部件的页面是**原样加载**的（自带 preload，不走壳、不走 iframe），
所以 `window.plugin` 就在页面自己身上——直接用裸 API 就行：

```js
window.plugin.onTick((data) => { /* 周期数据到了 */ });
window.plugin.data().then((data) => { /* 首份数据 */ });
window.plugin.act('click', { id: 1 });
window.plugin.window.setAlwaysOnTop(true);
window.plugin.window.setMode('window');   // 切回独立窗口
window.plugin.window.close();
```

**小部件收到的是裸数据**，不是 `{pluginId, data}` 信封——宿主推给小部件时已经把信封拆了。

（`bindSurface()` 在小部件里其实也能用：它先看自己身上的 `window.plugin`，找得到就用。
但既然裸 API 就在手边，没必要绕一层。真正要注意的是**数据的形状不一样**：
小部件那侧拿到的就是插件自己的数据，没有信封。）

**同一个插件如果既有 `window` 段页面又有 `widget` 段页面，就是两套 API、两套心智模型。**
能用一种就别用两种。

### 小部件的样子：共用一份卡片样式

小部件的窗口是**透明**的，界面自己带一块底。底的样子所有插件共用一份：
链 `/src/renderer/ui/widget.css`，用它的两个类。

```html
<link rel="stylesheet" href="/src/renderer/ui/widget.css" />
...
<div class="dp-widget-card">
  <div class="dp-widget-head">
    <span>标题</span>
    <span class="spacer"></span>
    <button id="expand" title="变回独立窗口">▣</button>
    <button id="close" title="收起来">✕</button>
  </div>
  ...
</div>
```

- `.dp-widget-card`：卡片本身（圆角、边、影、整块可拖）。
- `.dp-widget-head`：卡片的头。里面的按钮按 `no-drag` 处理——点按钮是点按钮，不拖窗口。

**小部件必须能关掉。** 宿主给小部件的窗口没有标题栏，用户手里没有别的办法收起它：
头的右边放一个「✕」（`window.plugin.window.close()`），
想留着的可以再给一个「▣」（`window.plugin.window.setMode('window')`）。

小部件页面原样加载、壳不参与，所以**这两个按钮得插件自己写**。

### 一个页面文件当两处用

上面说「两套 API」，但**页面可以只写一个**：`window` 段与 `widget` 段指向**同一个页面文件**，
再用 `bindSurface()` 里的 `surface.mode` 切布局。

`surface.mode` 告诉你页面开在哪儿：`'window'`（面板里或独立窗口）、`'widget'`（桌面小部件）。
是不是在面板里看 `surface.inPanel`（`true` 就是）。
```html
<body>
  <!-- 同一份 DOM，靠 body 上的类切紧凑版 -->
</body>
```

```js
const surface = bindSurface();
document.body.classList.toggle('dp-widget', surface.mode === 'widget');
```

数据形状在 `bindSurface()` 那里已经统一了：三种模式拿到的都是**裸数据**，
不用自己拆 `{ pluginId, data }` 信封。

`plugins/tasks/pages/board.html` 就是这么做的：
面板页、独立窗口、桌面小部件共用一个文件，小部件版靠 CSS 收起按钮那些。

### 窄版与宽版：页面按宽度自己切

同一个插件，在**面板**里与在**独立窗口**里是两种形态：
面板窄（420 宽），独立窗口宽（默认 640～860）。宽窄由**可用宽度**决定，断点 **560px**。

你的页面在两种形态下看到的是**自己的视口宽度**（面板里 ≈394，独立窗口里 = 窗口宽 − 2），
所以按宽度切版就行：

```css
/* 窄版是默认：面板里与小部件里都长这样。 */
#list { display: flex; flex-direction: column; }

/* 宽版：独立窗口里换一种排布。 */
@media (min-width: 560px) {
  #list { display: grid; grid-template-columns: repeat(2, minmax(0, 1fr)); }
}
```

**为什么是媒体查询而不是容器查询**：容器查询跨不过 iframe 边界——
你的页面在 iframe 里（另一个文档），查不到宿主外面的容器。
（宿主自己画的积木界面在同一个文档里，用的是 `@container surface (min-width: 560px)`；
那一套是宿主的事，插件页面用不上。）

**窄版别动**：面板里就靠它。用户把窗口拖到 560 以下，宽版会自己退回窄版——
这是设计要的效果，不是 bug。

`plugins/music-player/pages/player.html` 是宽窄两版的例子：
窄版竖着排，宽版左边播放器、右边歌单。

### 一个插件只能有一个窗口

宿主的窗口控制器是「一个插件一个窗口」，`window` 与 `widget` 互斥。
需要**同时开好几个窗口**（录屏的捕获页、选区遮罩、选区边框、控制条要一起开着），
就得自己 `new BrowserWindow()`——这时要自己写窗口管理与 preload。
`plugins/screen-recorder/lib/windows.js` 是一个完整的例子（也顺便看看它踩了哪些坑）。

## 8. 数据流：谁推给谁

```
                     ┌──────────────── 面板工作台（一个 surface）
   宿主 ──broadcast──▶ │
        ──broadcast──▶ └──────────────── 独立窗口（一个 surface）
        ──broadcast──▶ └──────────────── 桌面小部件（一个 surface）
```

- 宿主推给界面的东西**一律包成 `{pluginId, data}`**。
- 界面 `invoke` 回来的都是**裸值**。
- 一个插件**只有一个 tick 定时器**，不是每个界面一个（面板和窗口同时开着也是一份）。
- 定时器的周期按**挂着的界面里最快的那个**算：面板慢不该把小部件拖慢。
- `refreshMs: 0` → 不刷新。宿主只在界面的 `refreshMs` 上按周期调 `tick()`。
- 声明式界面的插件没有 `tick()` 时，宿主改成**重算一次页面**再推下去（番茄钟的倒计时靠这个）。
- **小部件也是一份 surface**：窗口开着就每秒推一份过去（它收的是**裸数据**）。
  界面落点在窗口建好时就挂上了——小部件的页面是原样加载的，没有壳替它报到。

import { mkdtemp, mkdir, writeFile } from 'node:fs/promises';
import { createPluginHost } from '../../src/main/plugins/host.js';

/** 摆一个插件目录。 */
async function makePlugin(root, id, manifest, main) {
  const dir = join(root, 'plugins', id);
  await mkdir(dir, { recursive: true });
  await writeFile(join(dir, 'plugin.json'), JSON.stringify(manifest, null, 2), 'utf8');

## 10. 常见坑

| 坑 | 怎么避开 |
|---|---|
| 目录名与 `id` 不一致 | 插件被静默跳过，只在日志里留一行。查 `src/main/plugins/loader.js` 的日志 |
| `entry` / `page` 写出了插件目录 | 被拒（`isSafeRelativePath`）。`../../` 能读到任意文件 |
| `toggle` 的动作值当成布尔 | 它是**字符串** `'true'` / `'false'` |
| `meta()` 里干了重活 | 带页面的插件，宿主每次开面板都会调 `meta()`。列系统窗口那种几百毫秒的活别放这儿 |
| `page()` 返回 `null` | 意思是「**关掉面板**」，不是「画个空页面」。想画空界面用 `emptyBlock` |
| 写了 `window.page` 但文件不在磁盘上 | 宿主退回积木界面（**这是好事**，不是白屏）。但那时 `page()` 就是必需的 |
| `win.webContents.id` 在窗口销毁后读 | 会把主进程整个冻住（「点了退出程序却不退」）。**销毁前存下来** |
| 小部件里用 `bindSurface()` | 小部件是原样加载的，用裸 `window.plugin` |
| 独立窗口里用 `window.plugin` | 独立窗口的页面在 iframe 里，用 `bindSurface()` |
| 切 tab 要等主进程回话才切 | **先本地切，再告诉主进程**。等回话才切 = 一次能感知的卡顿（录屏就踩过） |
| 每半秒收到一次数据就整个重画 | 重画会把打开着的下拉框关掉、把列表的滚动位置弄丢。**只在真的变了时**才改 DOM |
| 自己开的窗口抢了面板的焦点 | 面板失焦会自己收起来，界面落点一摘，页面就再也收不到周期数据（看着像卡死了）。浮窗用 `showInactive()` |
| 新建窗口时给的尺寸不生效 | Windows 会把**新建**窗口的尺寸夹到工作区（任务栏以外那块）。建成之后再 `setBounds` 才不被夹 |
| 插件在主进程里改坏了主进程 | **没有沙箱**。插件就是个普通 Node 模块，`import { app } from 'electron'` 随手可用 |
| 拿「模式」当下标去取数据 | 模式往往比数据的**种类**多：录屏有三个模式，可录目标只有显示器与窗口两类（选区用的是显示器）。直接拿模式下标，选区就去找一个根本不存在的桶，取数据时炸成 `Cannot read properties of undefined`。**先映射，再取**（见 `plugins/screen-recorder/lib/targets.js`） |

## 11. 宿主源码地图

要改宿主时看这里。**每份定义只有一份**，改的时候记得两边对齐。

| 文件 | 是什么 |
|---|---|
| `src/shared/plugin.js` | **插件清单与窗口规格的唯一契约**。改清单字段先改这里 |
| `src/shared/panel.js` | 界面积木的形状（`makePage` / `textBlock` / …） |
| `src/shared/assistant.js` | agent 的契约（风险等级、工具名的形状）——插件的工具清单也照它校验 |
| `src/main/plugins/paths.js` | 插件根目录：内置 = `<项目>/plugins`，用户 = `<userData>/plugins` |
| `src/main/plugins/loader.js` | 发现（扫目录、读清单、校验、去重）与加载（动态 import） |
| `src/main/plugins/host.js` | 注册、造 ctx、生命周期分发（`open`/`action`/`data`/`tick`/`act`/`refresh`）、开关插件、页面 URL 缓存；**插件的工具、技能与配置也在这里收集与注册** |
| `src/main/plugins/window.js` | 独立窗口与小部件的 `BrowserWindow`、壳与 iframe 的组装、窗口相关 IPC |
| `src/main/plugins/surface.js` | 界面路由：谁挂着这个插件、tick 定时器、广播 |
| `src/main/panel.js` | 面板的主进程侧；面板工作台也是一个 surface |
| `src/preload/plugin.cjs` | `window.plugin`（小部件与壳用） |
| `src/preload/panel.cjs` | `window.panel` 与 `window.panel.surface` |
| `src/renderer/ui/pluginPage.js` | `bindSurface()`——插件页面助手，自己认出身处面板还是独立窗口 |
| `src/renderer/ui/blocks.js` | 积木怎么画、动作怎么回传 |
| `src/renderer/ui/theme.css` | 共享设计系统 |
| `src/renderer/plugin-window/` | 独立窗口的「壳」 |
| `src/main/assistant/agent/skills.js` | agent 的技能表与 `skill.read` 工具 |

对应的测试在 `test/unit/plugin-{host,window-spec,surface,page-helper}.test.js`
与 `test/e2e/plugin-{surface,detach}.spec.js`。
