> 本文把那条路换成**插件面板**：左键点桌宠 → 弹出搜索框 → 模糊搜索 →

## 1. 目标与范围

### 1.1 要改的

| 现状 | 目标 |
| --- | --- |
| 右键菜单 →「小工具」子菜单（3 层） | **左键点桌宠** → 插件面板（搜索框 + 模糊匹配） |
| 菜单项只能「打开某个东西」 | 插件界面能**就地改数据**（勾待办、暂停番茄钟、填城市） |
| 「加一条待办」要绕道气泡的输入框 | 输入统一在插件界面里 |
| 待办/提醒清单塞在菜单项里 | 清单在插件界面里，是当下的 |

### 1.2 范围外

- 插件的**安装/分发**机制（第三方插件包）：本文的插件是**内置**的。
- 面板之外的全局热键（uTools 的 `Alt+Space`）：本文只有「点桌宠」这一条入口。
- 搜索**数据**（待办内容、文件、应用）：搜索的对象只有**插件**。

## 2. 总体架构

```
主进程 (src/main/)
├── plugins/index.js    插件注册表：定义、页面构造、动作分发
├── panel.js            插件面板窗口（独立窗口）
├── placement.js        「贴在桌宠旁边」的摆位算法（气泡与面板共用）
├── bubble.js           说话气泡（只剩 say 一种形态）
└── assistant/          桌面助理（插件读写的状态都在这边）
渲染层 (src/renderer/panel/)
└── main.js             面板页面：搜索视图 + 插件视图（只画，不做业务）
共享 (src/shared/)
├── fuzzy.js            模糊匹配（主进程与渲染层共用同一份）
└── panel.js            面板消息的形状
```

**主进程是唯一的状态来源。** 插件读写的都是助理的状态；
渲染层只负责呈现（画搜索结果、画插件界面）。

## 3. 插件面板窗口

### 3.1 三条硬约束

1. **懒创建**：第一次点桌宠时才建窗口。`app.firstWindow()` 认「第一个窗口」，
   面板若在启动时就建，E2E 会拿到面板而不是桌宠，整套套件超时。
2. **就绪握手**：面板页回 `panel:ready`，在那之前的视图排队等着。
   `webContents.send` 对尚未注册监听器的页面是**丢弃**而不是排队。
3. **失焦即收**：点面板外面就收起（300ms 抖动保护，躲开刚弹出时的假失焦）。

### 3.2 两个视图

| 视图 | 内容 | 键盘 |
| --- | --- | --- |
| 搜索 | 输入框 + 模糊匹配的结果列表 | ↑↓ 选、Enter 打开、Esc 关闭 |
| 插件 | 某个插件自己的界面 | Esc 回搜索 |

**同一个窗口**换内容，不另开窗口（uTools 就是这么做的）：
桌面上的浮窗数量不增加，用户也不必在两个窗口之间来回看。

### 3.3 位置与层级

摆位复用气泡那套「头顶 → 脚下 → 左侧 → 右侧，取第一个完整落在工作区内的位置」
（`src/main/placement.js`）——摆桌宠旁边，不打断视线。

层级用 `setAlwaysOnTop(true, 'screen-saver')`：桌宠用的是普通 `alwaysOnTop`
（`'floating'` 级），两个同级置顶窗口的相对顺序是未定义的——面板会被桌宠盖住。

### 3.4 后台节流

面板窗口必须 `backgroundThrottling: false`：隐藏的窗口会被 Chromium **冻结**，
面板收起来后再点开，页面要等它「醒过来」才画得出来，表现得像面板失灵。

## 4. 模糊搜索

`src/shared/fuzzy.js`（纯函数）：

- `fuzzyMatch(query, text)` → `{ score, positions } | null`
  1. **子串包含**（最常见）：分数最高，命中得越靠前、目标越短分越高；
  2. **子序列**：query 的字符按顺序出现即可；连续命中加分、词首加分、间隔扣分。
- `searchPlugins(query, plugins)` → 按分数降序排好；分数相同保持声明顺序。

**搜索在渲染层本地做**：插件清单一次性下发（`panel:plugins`），
每敲一个字不必过一次 IPC——那是这个交互手感的关键。

插件的搜索字段 = **名称 + 关键词 + 说明**，权重依次递减。
关键词里同时放英文与拼音（`todo` / `daiban` / `dai`），
这样「待办」「todo」「daiban」都能命中。

## 5. 插件模型

插件界面是**声明式**的：主进程造一份「页面描述」，渲染层照着画。

```jsonc
{
  "pluginId": "todos",
  "title": "待办",
  "subtitle": "还有 2 件事没做完",
  "status": "加好了：买菜",       // 底部那行提示
  "blocks": [
    { "kind": "text",    "text": "…" },
    { "kind": "list",    "items": [{ "id": "t-1", "label": "写周报", "done": false, "hint": "", "actionId": "t-1", "removeId": "" }] },
    { "kind": "input",   "id": "add", "placeholder": "要做什么？", "submitLabel": "添加", "value": "" },
    { "kind": "buttons", "items": [{ "id": "clear-done", "label": "清除已完成", "primary": false }] },
    { "kind": "toggle",  "id": "enabled", "label": "定时播报", "checked": false },
    { "kind": "empty",   "text": "（空）" }
  ]
}
```

交互约定（渲染层 → 主进程，单向 `send`）：

| 界面元素 | 动作 |
| --- | --- |
| 清单条目 | `{ pluginId, actionId: item.actionId, value: item.id }` |
| 输入框回车/提交 | `{ pluginId, actionId: input.id, value: 文本 }` |
| 按钮 | `{ pluginId, actionId: button.id, value: '' }` |
| 开关 | `{ pluginId, actionId: toggle.id, value: String(!checked) }` |
| 条目上的「×」 | `{ pluginId, actionId: item.removeId, value: item.id }` |

**插件是无状态的**：动作 → 重新 `open()` 一次 → 新的页面。
每个插件只有一份「我现在长什么样」的代码，
不会出现「改了数据但界面没跟着变」的第二套同步逻辑。

插件页面里所有字符串都来自主进程，渲染层**一律用 `textContent`** 画——
渲染层不是可信边界。

## 6. 插件清单

| id | 名称 | 界面 |
| --- | --- | --- |
| `todos` | 待办 | 清单（点一下勾完成）+ 输入框添加 + 清除已完成 |
| `reminders` | 提醒 | 清单（点一下删除）+ 输入框添加 |
| `pomodoro` | 番茄钟 | 状态 + 开始专注/开始休息/暂停/继续/重置 |
| `weather` | 天气 | 当前天气 + 设置城市 + 定时播报开关 |
| `clipboard` | 剪贴板 | 最近复制的内容 + 剪贴板助手开关 |
| `system` | 系统状态 | CPU / 内存 / 热状态 / 电源 |
| `history` | 聊天记录 | 和桌宠说过的话（清空） |
| `settings` | 设置 | 打开设置窗口（面板自己关掉） |

插件在注册表里按**声明顺序**排列——空查询时搜索结果就是这个顺序。

> ⚠️ **2026-11-02**：`launcher`（快捷启动）与 `speak`（说句话）两个插件**退役**。
> 快捷启动的能力变成了**搜索框里的程序搜索**（本机的程序与插件混排，
> 回车启动），说句话的能力被聊天盖住。详见 decisions.md #78~#85。

## 7. 助理接口的改动

插件要「读」状态，也要「改」状态。这两件事以前是混在「改完顺便弹个气泡」里的，
现在分成两组：

| 组 | 方法 | 返回 |
| --- | --- | --- |
| 读 | `todosView` / `remindersView` / `pomodoroView` / `weatherView` / `statusView` / `clipboardView` | 数据 |
| 改 | `addTodo` / `toggleTodo` / `addReminder` / `startPomodoro` / `setWeatherCity` … | `{ ok, message }` |

> ⚠️ **2026-11-02**：`launcherEntries` / `launchEntry` / `addLauncher` /
> `removeLauncher` / `speakText` 一起退役——前四个搬到了
> `src/main/apps.js` 的程序索引里（不再经过助理），最后一个被聊天取代。

改完**不弹气泡**（面板开着的时候，气泡横在上面会挡住内容），
只给桌宠一个情绪反应；`message` 由插件页面显示在底部。

随菜单一起退役的：`prompt` / `handleAction` / `askXxx` / `showXxx`。
它们的能力都搬进了插件页面。

## 8. 验收标准

1. 左键点桌宠 → 面板出现在桌宠旁边，**输入框自动聚焦**，且**不挡住角色**。
2. 输入「待办」/「todo」/「daiban」→ 待办插件排在最前。
3. 点结果或按 **Enter** → 同一个窗口换成该插件的界面。
4. 在待办插件里加一条 → 列表里立刻出现，且 assistant.json 里真的多了一条。
5. **Esc** 从插件界面回到搜索，再按一次关掉面板。
6. 右键菜单里**没有**「小工具」了。
7. 面板**懒创建**：应用启动时它并不存在。
8. `npm test` 全通过。
