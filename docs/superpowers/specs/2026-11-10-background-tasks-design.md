## 1. 背景与动机

后台任务（执行层）现在**只活在主进程的内存里**：

- 任务派出去以后，用户能看到的只有「桌宠说了一句『这件事做完了』」的气泡；
- 想问进展，只能回到对话框里问一句「刚才那个到哪了」，再等模型调用一次 `task.status`；
- 想停掉一个跑偏了的后台任务，只能靠自然语言让模型去调 `task.cancel`；
- 最要命的是**审批**：任务要写文件、要跑命令时，会在桌宠气泡上弹一个「需要你点头」。那个气泡是**一次性的**——被新消息顶掉就没了，而任务就卡在那儿不动了。

用户要的是：**后台有什么在跑、跑到哪一步了、要我点头的事，随时看得见，也随时能处置。**

现状是「运行时什么都有，就是没有出口」：队列、状态机、步骤事件、审批记录全都存在（见 §3），只是没有任何一条通路把它们送到界面上。

---

## 2. 目标与非目标

### 目标

1. **看得见**：一个界面同时列出当前所有后台任务——在跑的、排队的、在等你点头的、刚结束的。
2. **看得细**：每个任务说得出「它在干嘛、到第几步了、用了多久、结果是什么、为什么失败」。
3. **管得了**：在界面上能停掉一个任务、给它追加一句要求、把结束的任务归档。
4. **审批不再是一次性的**：待答的审批既能在桌宠气泡上答，也能在任务界面上答；两个口子指向同一份待答队列，**谁先答谁算数**。
5. **不撒谎**：界面上的每个数字都来自运行时，不做估算、不画假的进度条。

### 非目标（这轮不做）

- **任务的历史回放**：跑完的任务翻不到全过程（每一步调了什么工具、返回了什么）。那是聊天记录插件的活（`plugins/chat-history/` 的记录里已经有 `step`），这一轮不重复造。
- **任务的持久化**：任务不落盘，重启即没有（运行时本来就不存任务体，见 `2026-11-07-agent-runtime-design.md` §7.4）。
- **在气泡上加角标/宠物身上挂标**：气泡和宠物是「一句话」的载体，塞不进一个任务表。
- **给后台任务配参数、设优先级**：现在只有一个并发数（在设置里）。
- **审批策略可视化**：自动/分级/手动策略在设置里，界面不重复。

## 3. 现状盘点

| 能力 | 在哪 | 现在有没有出口 |
| --- | --- | --- |
| 任务队列 / 状态机 | `src/main/assistant/agent/runtime.js`（`queued/running/waiting_approval/done/failed/cancelled/interrupted`） | 没有。`agentTasks.list()` 存在，但**全工程没有一个调用者** |
| 任务精简视图 | `src/main/assistant/agent/tasks.js` `list()` / `counts()` | 没有（同上） |
| 停止 / 追加要求 / 归档 | `tasks.js` `cancel()` / `steer()` / `archive()` | 只有交互层的六个工具在用（`src/main/assistant/layer/taskTools.js`），得靠模型转述 |
| 步骤事件（跑到第几步、调了什么工具） | `loop.js` 的 `step` 事件；`tasks.js` 的 `lastSteps` 只留**最近一步的工具名** | 只进了聊天记录 |
| 审批闸门 | `src/main/assistant/agent/approval.js`（策略 auto/graded/manual、四个决定） | 只有气泡：闸门的 `ask` 回调直接调 `bubble.showApproval()` |
| 待答审批队列 | `src/main/bubbleApproval.js` 的 `createApprovalInbox()` | **私有在 `src/main/bubble.js` 里**，外面够不着 |
| 气泡上的审批卡片 | `src/main/bubble.js` + `src/renderer/bubble/main.js`（允许/拒绝/自动/取消任务四个按钮） | 有，且是**唯一**的入口 |
| 插件侧契约 | `src/main/assistant/agent/facade.js` 的 `createAgentFacade()`：`run/cancel/history/onEvent/tools` | `onEvent` 送的是**聊天记录条目**（kind/text/meta），不是运行时状态；也没有 `steer/archive/审批` |
| 插件形态 | `plugins/chat-history/`（自带页面，实时推数据）、`plugins/system/`（面板块 + 桌面小部件） | 现成的两个先例 |

两条已定的决策（本次设计的前提）：

- **形态**：新插件「后台任务」，一个**面板页** + 一个**桌面小部件**；
- **审批**：气泡与任务界面都能答，两个口子通向同一份待答队列，先答的算数。

## 4. 设计

### 4.1 形态：一个插件，三个落点

新插件 `plugins/tasks/`（目录名 = 清单 `id`，必须是 `tasks`）：

| 落点 | 清单字段 | 页面 | 说明 |
| --- | --- | --- | --- |
| 面板页 | `window.page` | `pages/board.html` | 完整任务板：待答审批 + 在跑/排队 + 已结束 |
| 独立窗口 | 同上（面板的「分离」按钮） | 同一个 `pages/board.html` | 同一个页面文件，宽一点 |
| 桌面小部件 | `widget.page` | **同一个** `pages/board.html` | 紧凑版：几个数字 + 在跑的任务 + 待答的一行 |

**面板页和独立窗口共用 `window.page`，小部件也指向同一个文件**——插件开发指南 §7 说「能用一种就别用两种」：这里只写一个页面文件、一套 `bindSurface()` API，靠 `surface.mode`（`'widget'` / 其它）切布局。小部件那边拿到的是**裸数据**（没有 `{pluginId,data}` 信封），`bindSurface()` 的 `unwrap()` 已经处理了这两种形状。

小部件与面板页共用一份数据契约（同一份快照、同一套动作 id），只是画法不同：

```
面板/窗口：小部件：
┌──────────────────────┐  ┌────────────────────┐
│ 后台任务  2 在跑 1 排队 │  │ 后台任务  2 在跑     │
├──────────────────────┤  │ ▸ 翻文件   12 秒     │
│ ⚑ 等你点头             │  │ ▸ 查天气   3 秒      │
│   写文件：notes.md     │  │ ⚑ 等你点头：写文件   │
│   [允许][拒绝][自动][取消]│  └────────────────────┘
├──────────────────────┤
│ ● 翻文件      进行中 12秒│
│   第 3 步 · fs.list      │
│   [停掉][追加要求]       │
└──────────────────────┘
```

### 4.2 数据通路：扩 `ctx.agent`（facade）

插件与 agent 之间**只有一条契约**：`src/main/assistant/agent/facade.js` 的 `createAgentFacade()`。它刻意不引 electron，所以能在普通 node 里测。扩它：

| 方法 | 语义 | 落到哪（在 `src/main/assistant/index.js` 的接缝里绑） |
| --- | --- | --- |
| `tasks()` | 当前任务的精简视图（**不含归档**） | `agentTasks.list()` |
| `cancel(taskId)` | 停掉一个任务 | `agentTasks.cancel()`（**已有**） |
| `steer(taskId, note)` | 给在跑的任务追加一句要求 | `agentTasks.steer()` |
| `archive(taskId)` | 把已结束的任务收起来（记录仍留着） | `agentTasks.archive()` |
| `approvals()` | 现在等着用户点头的审批 | `bubble.pendingApprovals()` |
| `answerApproval(id, decision)` | 答复一个审批（`allow/deny/always/cancel`） | `bubble.answerApproval()` |

不动的部分：

- `onEvent` **仍然是聊天记录条目**，不掺运行时事件（掺了会把 `plugins/chat-history/` 的页面弄脏）；
- 不新增「任务事件」通道——**每秒一次的快照已经够**（§4.7），加事件流是给自己找活干；
- `history()` 继续是记录，插件要用「上次退出时中断了几个任务」时从这儿数（§4.8）。

facade 里所有新方法在「底下没有接线」时都要**降级**（返回空列表 / `{ok:false,message:'后台任务运行时还没上线'}`），跟现在 `run()` 的 `NOT_READY` 一个口径。现有 `test/unit/agent-facade.test.js` 里的契约断言照着加。

### 4.3 任务快照长什么样

插件的 `data()` / `tick()` 返回一份**全量快照**（不是增量）：

```js
{
  tasks: [
    {
      taskId: 't-3',              // 运行时 id
      title: '翻文件',            // 一句话说明
      status: 'running',          // TASK_STATUS 里的原值
      lastStep: 'fs.list',        // 最近一步的工具名（没有就空串）
      stepIndex: 3,               // 已经走到第几步（没有就 0）
      result: '找到 12 个文件…',    // 完成时的结果摘要（截断 200 字）
      error: '',                  // 失败时的原因（没有就空串）
      elapsedMs: 12345,           // 还在跑就算到此刻
    },
  ],
  approvals: [
    { id: 't-3-1', taskId: 't-3', title: '需要你点头', text: '写文件：path=notes.md', risk: 'write' },
  ],
  counts: { running: 2, queued: 1 },   // 在跑含「等你点头」；归档的不算
}
```

**页面显示什么，一律由这份快照推导**，中文说法在插件页面里自己配一张状态表（跟 `plugins/chat-history/pages/format.js` 一个路子）：

| 状态 | 页面上的字 |
| --- | --- |
| `queued` | 排队中 |
| `running` | 进行中 |
| `waiting_approval` | 等你点头 |
| `done` | 已完成 |
| `failed` | 失败 |
| `cancelled` | 已取消 |
| `interrupted` | 被中断 |

**不画进度条**：一个任务总共几步，运行时不知道（`maxSteps` 是上限不是分母）。所以只说「第 N 步 · 工具名」+「用了多久」，剩下的不猜。

为此，`agentTasks.list()` 要多给两个字段（**现在没有**）：

- `error`：任务失败时的原因（从 `runtime` 的 `task.error` 取）。今天 `list()` 里没有它，失败的任务在界面上只能看见一个「失败」，看不到为什么。
- `stepIndex`：`tasks.js` 的 `lastSteps` 现在只存了工具名，改成存 `{ tool, index }`（`loop.js` 的 step 事件本来就带 `index`）。

这两个字段是**加**的：`task.list` / `task.status` 两个交互层工具只挑自己要的字段打印，输出不变。

### 4.4 审批：一个共享的待答队列

现在是「气泡自己有一个收件箱」：`src/main/bubbleApproval.js` 的 `createApprovalInbox()` 被 `src/main/bubble.js` **私有持有**，`src/main/assistant/index.js` 的闸门回调直接调 `bubble.showApproval()`。要让任务界面也能答，得把这份队列变成**两边共用**。

**归属不变**：收件箱仍然住在 `bubble.js` 里（它是「会弹卡片的那一方」），但对外多两个口子：

- `bubble.pendingApprovals()` → `[{ id, taskId, title, text, risk }]`（FIFO 顺序）
- `bubble.answerApproval({ id, decision })` → `{ ok, message }`

facade 把这两个口子透给插件（§4.2）。插件页面答审批 → `act('answer', { id, decision })` → 插件调 `ctx.agent.answerApproval(...)`。

**谁先答谁算数**：收件箱里一条审批只会被答复一次。第二次答复（气泡上点了、任务界面也点了）返回 `{ ok:false }`，界面提示「这个已经答复过了」，**不改任何状态**。

#### 待答队列的规则（要改的地方）

现在收件箱里**同时只能有一个**待答审批：气泡来新的请求时 `approvals.clear()` 把上一个作废（「气泡只有一只」），气泡一收（`hide()`）也作废。这套规则在只有气泡一个入口时说得通；一旦任务界面也能答，「作废」就变成**用户没点的请求被悄悄弄丢**——而任务还卡在那儿。

所以规则改成：

| 情形 | 现在 | 改成 |
| --- | --- | --- |
| 待答队列 | 同时只留一个 | **可以有多个**，FIFO |
| 气泡上的卡片 | 就是那一个 | 显示**队头**（最早发起的那个）；新来的排在后面，不打断正在显示的卡片 |
| 新请求到达 | 作废上一个 | 不作废，排队 |
| 气泡开流（聊天回复） | 作废待答审批 | **不作废**：卡片暂时让位，流结束后卡片自动回来；期间可在任务界面答复 |
| 气泡收起（隐藏桌宠等） | 作废待答审批 | **不作废**：请求还在队列里，任务界面仍然能答 |
| 应用退出 | 作废 | 仍然作废（判「没等到确认」，任务可以换条路） |
| 卡片被答复后 | — | 还有排队的就换下一个；没有了就收起气泡、放出排队的普通消息 |

「不作废」带来的后果要认：**桌宠被隐藏时，那个审批就没人看得见了**（气泡不在屏幕上），任务会一直挂着，直到用户在任务界面答掉或停掉它。这是有意的取舍——挂着的任务看得见、能停，比「被偷偷作废、任务闷头往下跑」好。（风险见 §7。）

闸门那边**不动**：`approval.js` 的 `ask` 回调仍然返回 `'allow'/'deny'/'always'/'cancel'`，`deny` 仍然喂回模型而不是杀掉任务，`cancel` 仍然真的停掉任务。

### 4.5 页面结构

页面是**自己写的 HTML**（不是声明式块）——声明式块表达不了「每个任务一行、每行可展开、每秒重画」。

```
pages/board.html      页面骨架 + 布局
pages/board.js        渲染与交互（DOM）
pages/format.js       纯逻辑：状态中文化、耗时格式化、快照分组（可单测）
```

分区：

1. **待你点头**：每个待答审批一张卡片——工具调用的说法（`describeToolCall` 的 `写文件：path=notes.md`）+ 四个按钮：**允许 / 拒绝 / 自动 / 取消任务**（与气泡上那四个一一对应）。卡片上标出是哪个任务。
2. **在跑与排队**：每个任务一行——状态点、标题、「第 N 步 · 工具名」、「用了 12 秒」，按钮：**停掉 / 追加要求**（追加要求展开一个输入框，回车提交）。
3. **已结束**：完成 / 失败 / 已取消 / 被中断的任务，收起成一栏，可展开看结果全文或失败原因，每行一个**归档**按钮。
4. **空态**：「现在没有后台任务」。

展开状态按 `taskId` 记（跟聊天记录页面一样）：重画时别把用户刚展开的那一行收起来。

### 4.6 动作语义

界面上能做的四件事，全部走插件的 `act`：

| 动作 id | 面板上的字 | 干什么 | 结果 |
| --- | --- | --- | --- |
| `cancel` | 停掉 | `agent.cancel(taskId)` | 任务进 `cancelled`；正在等审批的任务也会被唤醒（runtime 已有这个语义） |
| `steer` | 追加要求 | `agent.steer(taskId, note)` | 任务在步骤边界取走这句要求 |
| `archive` | 归档 | `agent.archive(taskId)` | 任务从列表里消失，**记录仍然留着**；在跑的任务不许归档（runtime 会拒） |
| `answer` | 允许/拒绝/自动/取消任务 | `agent.answerApproval(id, decision)` | 一次性的：先答的算数 |

失败要**如实说**：比如归档一个还在跑的任务，界面要显示 runtime 给的那句「这个任务还在跑，先停掉它再归档」，不能显示「已归档」。

动作做完不用等下一轮 tick：页面先把本地状态改成「已停掉」之类的样子，真正的状态由下一秒的快照确认。

### 4.7 刷新与重画

- **数据刷新**：清单里 `refreshMs: 1000`（面板/窗口/小部件都 1000）。宿主的 tick 定时器每个插件一个（`src/main/plugins/surface.js`），只在有界面挂着的时候跑。**每秒一次快照，够用**——不引事件流。
- **重画**：页面收到新快照后**就地更新**：按 `taskId` 复用已有的行节点，只改变化了的文字和 class；行的增删按 `taskId` 对齐。
  - 不能整页重画：用户正在输入「追加要求」的那句话会被抹掉；刚展开的行会收起来。聊天记录页面已经踩过「重画把展开的收起来」的坑。
- **耗时**：`elapsedMs` 由快照给，页面每秒刷新一次文字。

### 4.8 重启之后

运行时不存任务体，重启后任务全没了——但**记录里有线索**：启动时 `record.js` 的 `interruptedTasks()` 会给上次退出时还在跑的任务各补一条 `interrupted` 的任务记录（`src/main/assistant/index.js` 里已经这么做了）。

任务界面据此在顶上给一行说明：**「上次有 2 个任务被中断」**。这条数从 `ctx.agent.history()` 里数（`kind === 'task'` 且 `meta.status === 'interrupted'` 的条数）。

**不做假恢复**：不假装任务还能接着跑（运行时确实没有它了）。要接着干，重新派一个。

## 5. 依赖与顺序

每一期都写明「怎么算做完了」，照着 CLAUDE.md §4 的验收口径来。

| 期 | 做什么 | 验收 |
| --- | --- | --- |
| **T1** | facade 扩接口（`tasks/steer/archive/approvals/answerApproval`）；`agentTasks.list()` 多给 `error` 与 `stepIndex` | 单测：facade 新方法在「底下没接线」时降级不报错；接线后返回值形状对；`list()` 的两个新字段有值 |
| **T2** | 审批收件箱改成多待答 + FIFO；气泡按队头显示卡片；开流/收气泡不再作废待答审批；`bubble.pendingApprovals()` / `bubble.answerApproval()` | 单测（收件箱是纯逻辑，好测）：多个待答按 FIFO 出队、先答的算数、重复答复返回失败、退出时才作废。e2e：老的气泡审批用例（`test/e2e/approval-bubble.spec.js`）**必须原样通过** |
| **T3** | 新插件 `plugins/tasks/`：清单 + `pages/board.*`；只读的任务板（面板页 + 小部件） | e2e：面板里搜到「后台任务」→ 打开 → 看得见派出去的任务（在跑 / 等你点头）；小部件窗口能开出来并显示同样的数据 |
| **T4** | 动作：停掉 / 追加要求 / 归档 / 在任务界面答复审批 | e2e（照 `approval-bubble.spec.js` 的桩模型走）：任务在任务界面上被停掉；审批在任务界面上答「允许」→ 工具真的执行了（文件写出来了）；归档后任务从板上消失但记录还在 |

T2 是唯一动到既有交互的一期，**风险最高，放在最前面单独验**。

## 6. 测试策略

**单测**（`test/unit/`，node:test，不起 electron）：

- facade 新契约（接线的 / 没接线的两种）；
- `agentTasks.list()` 的 `error` 与 `stepIndex`；

- 面板里搜到插件 → 打开 → 看见在跑的任务与它的状态；
- 小部件窗口能开出来。

## 7. 风险与未决

| 风险 | 说明 | 怎么办 |
| --- | --- | --- |
| **T2 改的是老行为** | 「开流/收气泡作废待答审批」是现有语义，撤掉之后待答审批会挂更久 | T2 单独做、单独验；`approval-bubble.spec.js` 原样必须过；气泡不答时任务界面能答（兜底） |
| **桌宠隐藏时审批看不见** | 气泡不在屏幕上，待答审批只剩任务界面能看见 | 任务界面是常驻插件（默认启用）；任务在板上看得见、也能停 |
| **两个界面同时答同一个审批** | 谁先答算数，后来的要收到「已经答复过了」 | 收件箱一次性的语义就是干这个的；e2e 覆盖 |
| **每秒快照的开销** | 每个插件一个定时器，只在界面挂着时跑 | 快照是纯内存读（`runtime.list()`）；任务多了也就几十条 |
| **页面重画抹掉输入** | 用户正在输入追加要求时重画 | 就地更新、按 `taskId` 复用行节点（§4.7） |
| **小部件与面板页共用一个页面文件** | 指南 §7 提醒过「两套 API」 | 这里只写一个文件、一套 `bindSurface()`，靠 `surface.mode` 切布局；数据契约完全一致 |

**未决**：

1. 待答审批多了以后，气泡是不是该显示「还有 1 个在排队」？这一轮先不显示（队头答完自然换下一个），看用起来再说。
2. 归档的任务要不要能「取消归档」？runtime 的 `archive()` 只有归档，没有还原——这一轮不做还原，界面上不给这个按钮。
3. 要不要给任务界面接 agent 工具（让模型能读界面上的东西）？没必要，`task.list` / `task.status` 已经能做这件事。
