# 桌宠「先应一声」与 think 模式 · 设计

> 日期：2026-11-08
> 状态：已实现
> 范围：`src/main/assistant/chat/`（两个新模块）+ 大模型客户端 + 设置页

---

## 1. 背景

两件事，都是「桌宠显得不够像人」。

**其一：等待期是哑的。** 用户问一句「F 盘 video 下有什么」，agent 要调工具、要再问一次模型，
整个过程好几秒。这几秒里桌宠一声不吭，用户只看到一只空气泡，
心里想的是「这程序是不是坏了」。

**其二：think 模式是隐藏开关。** 有些模型（比如 MiniMax 那一系）先思考再回答，
思考得越深答得越好，但也越慢越费额度。这个取舍该由用户做，
而不是写死在代码里。

## 2. 先应一声

### 2.1 时序

```
用户发话
  │
  ├─ 0ms    计时开始（ACK_DELAY_MS = 1200）
  │
  ├─ 模型吐出可见正文？ ── 是 ──→ 取消应答，直接放答案气泡
  │        │否
  │        ↓
  ├─ 1200ms  随机挑一句短句 → **单独一只气泡** + 朗读
  │        │
  │        ├─ 朗读中模型就答完了？正文先攒着，**不打断朗读**
  │        ↓
  ├─ 朗读结束（或兜底超时 8s）→ 答案气泡打开 → 正文一次性倒出来
  │
  └─ 定稿 → 气泡开始计时自动消失
```

### 2.2 为什么是固定短句

让模型先说一句要多等一轮请求——那一轮正是这里想省掉的时间。
固定短句零延迟、零花费，念出来也快。

随机是为了别每次都同一句：用两天就腻了。

### 2.3 答案气泡为什么不能立刻开

应答和答案是两句话。挤在同一个气泡里，用户会把前半句当成答案的一部分。
所以答案气泡**必须**等应答念完才开，哪怕答案正文早就到了。

正文到了但气泡还没开时，正文**攒着**（`chat/stream.js`），
开的时候一次性倒出去——用户看到的是完整回复，不会先看到半句再看到另一半。

### 2.4 「念完了」这个信号从哪来

渲染层播完音频时回报一个 id（`pet:speechEnded`），主进程才知道这一声念到哪了。

兜底叠了三层，任何一层不出问题都不会把界面卡住：

| 兜底 | 时长 | 兜什么 |
|---|---|---|
| 渲染层回报 | — | 正常路径 |
| 主进程超时 | 10s | 窗口被关、回报丢了 |
| 应答超时 | 8s | 语音合成卡住、渲染层没回 |

### 2.5 放行规则（写错了会卡死）

答案气泡等的是「应答念完」，所以**放行**得看应答处于哪种状态：

| 状态 | 放行吗 |
|---|---|
| 还没应答（计时器没到 / 压根没上计时器） | 放行——不必等了 |
| 已经应答，正在念 | **不放行**：那一声念完才轮到答案 |
| 出错了 / 被新一轮取代 | 放行——这一轮没有答案了 |

「压根没上计时器」指的是**主动搭话**那一轮：桌宠自己开口，没人需要它「应一声」。
那一轮同样要走放行逻辑，否则这一轮会永远卡在「等应答」上，答案永远不冒出来。

### 2.6 应答要插队

上一轮的回答还挂在气泡上时，应答**必须插队**（`interrupt: true`）：
不插队的话它会排到上一轮回答后面，用户先看到的还是那句旧回答，
等它自己消失才轮到应答——那就白等了。

同理，「这个模型不支持 think」的提醒也要插队。

## 3. think 模式

### 3.1 状态

```
llm.think        开关：开 / 关
llm.thinkLevel   深度：low / medium / high
```

只有这三个深度值（`src/shared/assistant.js` 的 `THINK_LEVELS` 是唯一定义）。
磁盘上的值认不出来时当「中」。

### 3.2 请求里发什么

| 状态 | 发出去的字段 |
|---|---|
| 开 | `thinking: {type:'adaptive'}`、`reasoning_split: true`、`reasoning_effort: <深度>` |
| 关 | `thinking: {type:'disabled'}` |
| 退路 | **什么都不发** |

「退路」是给不认这些参数的模型用的（见 §3.4）。

`reasoning_split` 是为了把思考内容**拆开**单独返回。不拆的话思考带着
`<reasoning_content>` 标签混进正文，气泡里会冒出一堆胡话。

即便服务端不拆，客户端也会把内联的 `<reasoning_content>…</reasoning_content>`
**剥干净**（`createReasoningStripper`）——思考内容是模型心里的想法，
绝不能进气泡。标签可能跨 chunk 边界，剥的时候要按住「可能是标签前缀」的尾巴。

### 3.3 深度映射

| 档位 | `reasoning_effort` |
|---|---|
| 低 | `low` |
| 中 | `medium` |
| 高 | `high` |

### 3.4 模型不认这些参数怎么办

有的模型见到 `thinking` / `reasoning_effort` 就 400。
那样的话用户只会看到「接口返回 HTTP 400」——他根本不知道
是自己刚打开的 think 模式惹的祸。

所以：

1. 400 的原文里提到 `thinking` / `reasoning` 时，**去掉 think 参数在同一个地址上再试一次**；
2. 成功了就告诉用户一句（气泡提醒），并**记住这个模型**——
   同一个模型再问时直接不发这些参数，不再每轮都撞一次 400；
3. 换个地址重发是没有意义的（别的 400 与 think 无关），所以只有这一种 400 才走退路。

提醒的口气分两种：开着 think 时是「不支持，我按普通模式来啦」，
关着时是「不认这个开关，普通模式也一样」——用户本来就不要 think，没什么可惊讶的。

### 3.5 设置页

```
[✓] 启用 think 模式
    思考深度  [低 | 中 | 高]      ← 开关关着时这一栏是灰的
```

开关关着时把深度灰掉：不灰的话用户会以为「中」正在生效。

## 4. 代码地图

| 文件 | 干什么 |
|---|---|
| `src/main/assistant/chat/ack.js` | 应答控制器：计时、挑短句、放行答案 |
| `src/main/assistant/chat/stream.js` | 答案气泡的「攒着—开流—定稿」时序 |
| `src/main/assistant/llm/openai.js` | think 字段、思考内容剥离、400 退路 |
| `src/main/assistant/index.js` | 把上面三样接到一轮对话上 |
| `src/shared/assistant.js` | `THINK_LEVELS`、`DEFAULT_LLM.think` |

`ack.js` 与 `stream.js` 都不引 electron，能脱离 Electron 单测——
这段时序很容易写坏（写了就丢、或者攒着攒着不倒出去），所以它自己是一个单元。
