## 1. 目标与范围

### 1.1 要补的

| 现状 | 目标 |
| --- | --- |
| 桌宠只能手动启动 | **开机自启**：登录 Windows 后自动拉起 |
| 桌宠只能从托盘唤出 | **全局快捷键**：一个组合键呼出/隐藏 |
| 桌宠始终吃住一块桌面 | **穿透模式**：鼠标点不到它，桌面照常操作 |
| 拖到边缘会被硬夹住 | **边缘吸附 + 贴边停靠**：贴齐边缘，或干脆藏起来只留一条边 |
| 设置面板缺「音量」 | **总音量**：一个滑块同时管提示音与语音 |

### 1.2 范围外

- **托盘菜单的「开机自启」勾选项**：自启状态在设置窗口里改就够了，托盘菜单保持短。
- **多显示器各自的停靠边**：停靠边是全局一个值（`dock`），不是每屏一份。
- **ASR / 语音唤醒**：属第四部分，不在本文。
- **Linux / macOS 的自启与快捷键差异**：本项目只做 Windows（见 `decisions.md` 关于 `activate` 事件的裁决）。

## 2. 总体架构

```
                        ┌──────────────────────────────┐
  settings.json  ◀─────▶│  system.js（控制器）          │
  （六个新字段）         │  · 开机自启：登录项注册        │
                        │  · 全局快捷键：注册/注销/录制   │
  assistant.json ◀──────▶│  · 穿透模式：setIgnoreMouseEvents│
  （sound.volume）       │  · 边缘吸附与贴边停靠：状态机 + 位置│
                        └───────┬──────────────┬────────┘
                                │              │
                    edgeDock.js（纯几何）      │ 广播
                                │              ▼
                                │        renderer/main.js
                                │        （音量 → masterGain）
                                ▼
                        桌宠窗口 BrowserWindow
```

**主进程仍是唯一的状态来源**：`settings.json` 存六个新字段，`assistant.json` 存音量。
渲染层只负责呈现与播放。

### 2.1 模块划分

| 文件 | 职责 | 为什么单独一个文件 |
| --- | --- | --- |
| `src/main/system.js` | 系统级开关的生命周期：落盘 → 启动恢复 → 变更生效 | 这些开关共享同一套流程，放一起能互相看见 |
| `src/main/edgeDock.js` | **纯函数**：间隙、吸附目标、停靠位置、停靠判定 | 几何计算最容易算错，必须能脱离 Electron 单测 |

`src/main/index.js` 只增加接线代码，不放业务逻辑。

### 2.2 依赖注入

`system.js` 以工厂函数导出，外部能力全部注入，便于单测：

```js
createSystemController({
  getWindow,        // () => BrowserWindow
  getDisplays,      // () => displays[]
  getSettings,      // () => settings
  applySettings,    // (patch) => settings   —— 复用 index.js 的 persist()
  onHotkeyAction,   // () => void            —— 呼出/隐藏
  onStateChanged,   // () => void            —— 状态变了（菜单要重建）
  loginItem,        // { set(settings), get() }  —— 默认用 app.setLoginItemSettings
  shortcuts,        // { register, unregister, unregisterAll, isRegistered }
  isE2E,            // boolean
})
```

`loginItem` 与 `shortcuts` 默认实现包住 Electron 的 `app.setLoginItemSettings` /
`globalShortcut`；单测注入替身，E2E 注入不碰注册表的替身。

`onStateChanged` 用来重建托盘菜单——托盘菜单只在启动时构建一次，
勾选状态（「鼠标穿透」）与「取回桌宠」的出现都要靠重建来同步（§5.2、§6.5）。

## 3. 开机自启

### 3.1 状态

`settings.autoLaunch`：布尔，**默认 `false`**。

不自启是默认：开机就跑一个桌宠是用户没要求的行为。

### 3.2 注册参数

```js
app.setLoginItemSettings({
  openAtLogin: true,
  path: process.execPath,
  args: app.isPackaged ? [] : [app.getAppPath()],
});
```

**开发态必须带 `args`**：开发时 `process.execPath` 是 `node_modules/electron/dist/electron.exe`，
不带应用路径的话开机只会弹一个空白的 Electron 窗口。
打包后 `process.execPath` 就是应用自己的 exe，不需要参数。

### 3.3 不做「开机静默启动」

Electron 45 **已经移除了 `openAsHidden`**（核对 `node_modules/electron/electron.d.ts`：
`Settings` 接口只剩 `openAtLogin` / `type` / `serviceName` / `path` / `args` / `enabled` / `name`）。
要实现「开机自启时不弹出来」得自己约定 `--hidden` 参数并在启动时读 `process.argv`。

**不这么做**，两个理由：

1. 桌宠窗口用的是 `showInactive()`——**不抢焦点**，开机弹出来不会打断用户正在做的事；
2. 「上次是不是可见」本来就记在 `settings.visible` 里。用户想开机时看不到桌宠，
   退出前藏起来即可，不需要另一个机制。

### 3.4 失败处理

`setLoginItemSettings` 抛错时：

1. 终端留痕（`console.warn('[desk-pet] 开机自启设置失败：', err?.message)`）；
2. **把 `autoLaunch` 改回 `false`**——不能让磁盘写着 `true` 而系统里没有注册项；
3. 广播设置，设置窗口显示失败。

### 3.5 E2E 不得写注册表，也不得占用系统级快捷键

`DESK_PET_E2E` 为真时：

- `loginItem` 换成只记录调用的替身，**不碰注册表**。
  写注册表会污染跑测试的机器，而且注册表项可能指向临时路径，清理不掉。
- `shortcuts.register` 同样换成替身（**假装注册成功**），
  **不真的占用系统级快捷键**。
  `globalShortcut.register` 是全局生效的：E2E 跑测试的那几分钟里，
  用户按 `Ctrl+Shift+D` 会被桌宠吃掉——影响的是跑测试的整台机器。

替身「假装成功」是为了让「注册状态被正确上报」那条链路在 E2E 里仍然跑得通；
**真实注册只能人工验证**（§10.3）。

## 4. 全局快捷键

### 4.1 状态与默认值

`settings.hotkey`：字符串，默认 `'Control+Shift+D'`。动作 = **呼出/隐藏桌宠**
（与托盘菜单的「显示 / 隐藏」是同一个动作）。

### 4.2 录制由主进程主导

渲染层只负责「开始录制」这一个动作，快捷键串由主进程拼装：

```
设置窗口点「重新录制」
   │ pet:recordHotkey
   ▼
主进程 recording = true
   │ 设置窗口 webContents.on('before-input-event', …)
   │   input = { key, control, alt, shift, meta }
   ▼
拼成加速键串 → 校验 → 注册 → 落盘 → 回播状态
```

`before-input-event` 给的 `input.key` 与修饰键位正好是 Electron 加速键格式需要的
（`node_modules/electron/electron.d.ts` 的 `Input` 接口）。

### 4.3 两条硬规则

**① 必须至少带一个修饰键。**
Windows 的 `RegisterHotKey` 允许注册裸键——那意味着全局劫持用户的字母键，
「按 D 一下」会同时被桌宠吃掉。裸键一律拒绝。

**② 录制期间 `event.preventDefault()`。**
否则那一次按键会漏进设置页面的输入框（比如正在编辑城市名时按了 Ctrl+Shift+D，
城市名里就多出一串字符）。

Esc 取消录制。

### 4.4 冲突处理

`globalShortcut.register(acc, cb)` 在组合被别的程序占用时**返回 `false` 且不抛错**
（Windows 上是静默失败，Electron 的文档明说这是操作系统的有意行为）。

因此：

- 注册失败 → 设置窗口明确显示「**该组合已被其他程序占用**」，不写盘；
- **换组合时先注册新的，成功了再注销旧的**：注册失败时旧组合原样保留，
  用户不至于连原来的快捷键也丢掉；
- 记录的新组合与当前相同 → 视为成功，不重复注册（`register` 同一个加速键会返回 `false`）。

### 4.5 快捷键的动作细节

按下快捷键时：

- 桌宠不可见 → 显示它；
- 桌宠可见 → 隐藏它；
- **桌宠处于停靠状态且要被显示** → 先**取回**（完全可见），再显示。
  用户召唤桌宠是想看见它，不是想看 24px 的一条边。

### 4.6 生命周期

- 启动时按 `settings.hotkey` 注册一次；注册失败只留痕 + 在设置窗口显示状态，不阻断启动。
- 退出时 `globalShortcut.unregisterAll()`。
- 切换组合时**先注册新的、成功了再 `unregister` 旧的**（不是先 `unregisterAll()`——
  那会把刚注册成功的新组合一起注销掉）。任何时刻只有一个有效组合。

## 5. 穿透模式

### 5.1 状态与生效

`settings.clickThrough`：布尔，默认 `false`。

```js
win.setIgnoreMouseEvents(true, { forward: true });
```

`forward: true` 让 **mousemove 继续送到渲染层**——桌宠仍然能跟着光标转头，
但点击落到桌面上。这是「桌宠在桌面上但不妨碍你干活」的关键。

### 5.2 入口

- 设置窗口「系统」分区；
- 托盘菜单与右键菜单的勾选项（两项都叫「鼠标穿透」）。

菜单是**每次弹出时重新构建**的（右键菜单），但**托盘菜单只在启动时构建一次**——
所以状态一变就要 `tray.setContextMenu(...)` 重建，否则勾选状态会一直是旧的。

### 5.3 与停靠的关系

互不排斥，可以同时开。

- 都开：桌宠既点不到，也只露一条边——此时唯一的召回方式是快捷键或托盘菜单。
  这是合理的：用户主动开了穿透，等于说了「我不想碰它」。

## 6. 边缘吸附与贴边停靠

### 6.1 两个开关

| 设置 | 默认 | 含义 |
| --- | --- | --- |
| `settings.edgeSnap` | `true` | 拖到屏幕边缘附近时**自动贴齐** |
| `settings.dockEnabled` | `false` | 贴齐后**滑出屏幕**，只留一条边 |
| `settings.dock` | `null` | **当前**停靠在哪条边（状态，不是开关） |

「贴边停靠」必然包含吸附——要藏起来得先贴齐。两个开关分开，是因为
「我要它贴着边但别藏起来」是一个合理诉求。

`dockEnabled` 与 `dock` 分开：前者是**用户的意图**（要不要这个功能），
后者是**当前状态**（现在藏在哪条边）。设置页上的「贴边隐藏」勾选框
读 `dockEnabled`，而 `dock` 是状态——桌宠已经停靠时，勾选框仍然是勾上的。

`settings.dock` 的值：`'left' | 'right' | 'top' | 'bottom' | null`。

### 6.2 几何（`edgeDock.js` 纯函数）

工作区 `wa`（`{x, y, width, height}`），窗口 `w×h`，位置 `(x, y)`。

四个间隙：

```
gapLeft   = x - wa.x
gapRight  = (wa.x + wa.width) - (x + w)
gapTop    = y - wa.y
gapBottom = (wa.y + wa.height) - (y + h)
```

正数 = 还差多少才贴齐；负数 = 已经越出屏幕。

**吸附（拖拽过程中实时生效）**：

1. 某条边的间隙 `gap ∈ (0, 24]`；
2. **且本帧的位移是朝那条边去的**（右边看 `dx > 0`，左边看 `dx < 0`，
   上边看 `dy < 0`，下边看 `dy > 0`）；

两条同时成立 → 把该间隙归零，窗口贴齐。多边同时满足时取间隙最小的那个。

**条件 2 是必须的**：没有它，窗口贴上边之后往回拖会被立刻吸回去——
用户会发现「拽不动」。加上它，窗口一离开边缘就自由了。

**停靠状态下不吸附**——否则「往外拽」这个动作会被吸附顶回去。

> 现有的 `clampToDisplays` 已经让窗口在被推到底时贴住边缘，
> 所以吸附真正的价值是**「推近了自动磁过去」**这一下。

**停靠位置**（右边缘为例，`R = wa.x + wa.width`）：

| 状态 | x |
| --- | --- |
| 完全可见、贴齐 | `R - w` |
| 停靠（只露 24px） | `R - 24` |

其余三条边对称。停靠后窗口**大部分在屏幕外**，屏幕上只露出贴着该边的那 24px
（贴右边时是窗口的**最左边** 24px，贴左边时是**最右边** 24px）。

### 6.3 夹紧要放宽

现在的 `clampToDisplays` 把窗口整个按回工作区内——停靠根本出不来。

停靠时沿**停靠轴**放宽，垂直轴照常。放宽后的区间是
**「藏匿区 ∪ 普通可见区」**：

| 停靠边 | 允许区间 | 含义 |
| --- | --- | --- |
| right | `x ∈ [wa.x, R - 24]` | 从工作区最左端（完全可见）到完全藏起 |
| left | `x ∈ [wa.x + 24 - w, R - w]` | 从完全藏起到工作区最右端（完全可见） |
| top | `y ∈ [wa.y + 24 - h, B - h]` | 从完全藏起到工作区最下端（完全可见） |
| bottom | `y ∈ [wa.y, B - 24]` | 从工作区最上端（完全可见）到完全藏起 |

（`R` = 工作区右边界，`B` = 工作区下边界。）

**为什么是「并上普通可见区」而不是只用藏匿区 `[贴齐位, 藏起位]`：**
只用藏匿区的话，把桌宠从边缘拽出来时它只走那一段（窗宽 − 24 ≈ 276px）就停住，
剩下的一段要**再拖一次**才跟得上——「把桌宠挪到屏幕中间」变成两次手势。
并上普通可见区之后，一次手势就能把它拖到任何地方。

> **区间必须包含它自己的停靠位**（`dockPosition(side)` 落在区间内）。
> 这条是被实现者的一条守卫测试钉住的——规则写反了的话，
> 上下停靠会「一拖动就被夹出藏匿区」，等于上下停靠根本不存在。

> 早先这里只写了藏匿区 `[R-w, R-24]`。那是 Task 7 的审查暴露出来的：
> 实现的逐字代码来自那份规格，于是缺陷也原样落进了代码。

### 6.4 何时停靠

**拖拽结束时**判定，三个条件同时成立：

1. 窗口与某条边**贴齐**（该边 `gap == 0`）；
2. **本次拖拽的净位移是朝那条边推的**（往右推 `netDx > 0`，往上推 `netDy > 0`……）；
3. 净位移**不小于 8px**（`MIN_DOCK_PUSH`）——否则一次轻微的抖动就能把桌宠藏起来。

左右只可能命中一侧（`netDx` 不可能既正又负），上下同理，所以最多两个候选，
取位移大的那个。

条件 1 之所以成立，是因为**吸附（§6.2）已经把窗口贴齐了**——
推近边缘时它就磁过去了。

> **条件 2 与 3 是必须的**：桌宠默认停在主显示器右下角，
> 而右下角**正好贴着两条边**。没有「朝哪边推」这一条，任何一次轻微拖动都会让它消失。

**从 `docked` 状态出发的这一趟拖拽不判定停靠**（§6.5）——「拽出来」是明确的意思，
不该在同一趟拖拽的末尾又塞回去。

### 6.5 状态机

```
free ──拖到边缘并贴齐、松手──▶ docked
docked ──拖那条边把它拽出来──▶ free
```

**free → docked**：拖拽结束时按 §6.4 判定。停靠时窗口滑出到「只露 24px」。

**docked → free**：拖拽时沿停靠轴放宽（§6.3），把窄边拽出来即可。
拽出来之后**这一趟不再判定停靠**——「拽出来」本身就是明确的意图，
不该在同一次拖拽的末尾又把它塞回去。

**停靠状态下不能换边**：要先拽出来。原因见 §6.6。

**拽出来 276px 有点长**，所以另给一条出路：菜单里多一项「**取回桌宠**」——
托盘菜单与右键菜单都有，**仅在停靠时出现**。

> 托盘菜单只在启动时构建一次，所以「取回桌宠」的出现与消失都要求
> **停靠状态一变就重建托盘菜单**（§7.1 同理，鼠标穿透的勾选状态也靠重建来同步）。

### 6.5.1 关掉开关时的取回

- **关掉「贴边隐藏」而桌宠正在停靠** → 桌宠**立即取回**（回到完全可见的贴齐位）。
  不这么做的话，用户关了「贴边隐藏」，桌宠却还赖在屏幕外——开关看起来没生效。
- **关掉「边缘吸附」** → 不影响已停靠的桌宠（停靠本来就包含贴齐）；
  但从停靠取回后，拖拽不再有磁吸效果。

### 6.6 为什么不能一边停靠一边换边

停靠时窗口**大部分在屏幕外**。此时把「上边贴齐」当成停靠到上边，
窗口会横着卡在屏幕右外侧、只在上边露一条——那是个用户没要求过的位置。

规则：**停靠时只沿停靠轴拽出，垂直方向可以在工作区内自由移动但不触发停靠。**

### 6.7 位置记忆

停靠时持久化的**不是**窗口的真实位置（那在屏幕外，重启后会被
`restorePosition` 判定为「不在任何显示器内」而回落到主显示器右下角），
而是：

- `settings.position` = **完全可见贴齐时的位置**（`R - w`）；
- `settings.dock` = 停靠边。

启动时先按 `settings.position` 恢复窗口，再施加停靠 → **重启后仍然停靠**。

### 6.8 与现有拖拽逻辑的接缝

现有 `onMoveBy` 是「期望位置累加增量 → 夹紧 → 落盘」。改动点：

1. **夹紧**：free 时仍用 `clampToDisplays`（多显示器语义不变），
   docked 时改用放宽后的夹紧（§6.3），工作区取**停靠所在显示器**的。
2. **吸附**：free 时在夹紧**之后**实时做（§6.2），用本帧的位移判断「朝哪边」。
3. **落盘**：docked 时存「完全可见贴齐位」而不是真实位置（§6.7）。
4. **拖拽开始**（`onDragStart`）：期望位置重置为**当前真实位置**——
   docked 时那是「屏幕外的大半」，从它起算才能把窄边平滑拽出来。
5. **拖拽结束**（`onDragEnd`）：按 §6.4 判定停靠。

### 6.8.1 「净位移」用的是期望位置，不是窗口的实际移动

停靠判定里的条件 2 与 3 用的是**期望位置**的净变化（`desiredPosition` 减起点），
而条件 1 用的是**窗口实际位置**的间隙。

理由：窗口被推到屏幕边缘后就被夹住不动了，此时**期望位置还在继续累加**。
用户「把桌宠往右推」这个动作，在窗口的实际位移上是 0（它已经贴边了），
在期望位置上是正的——只有后者表达了意图。

代价：用户把桌宠推到右边缘后**多推了一段**（期望位置越过了边界），
再往回拉时窗口会「慢半拍」才跟上。这是夹紧的固有行为，现有拖拽已经如此
（`desiredPosition` 本来就是为它设计的），不新增问题。

## 7. 设置窗口

### 7.1 新增第 6 个分区「系统」

现有分区：外观 / 助理 / 语音 / 对话 / 记忆。新增「系统」放在**最后**。

```
系统
开机自启、快捷键、穿透与贴边——这些是桌宠与系统的关系。

[✓] 开机自启
     登录 Windows 后自动启动桌宠

快捷键          Control+Shift+D   [重新录制]
                呼出 / 隐藏桌宠。被别的程序占用时这里会写明。

[ ] 鼠标穿透
     开启后点不到桌宠，桌面照常操作

[✓] 边缘吸附
     拖到屏幕边缘时自动贴齐

[ ] 贴边隐藏
     贴齐后滑出屏幕，只留一条边；拖那条边可以把它拉回来
```

目录摘要沿用现有风格（助理分区是 `3/6`）：这一分区共 5 项
（开机自启 / 快捷键 / 鼠标穿透 / 边缘吸附 / 贴边隐藏），
摘要显示其中启用了几个（如 `2/5`）。快捷键非空即算「启用」。

### 7.2 「语音」分区加「音量」

```
音量            [──────●────] 80%
```

放在「语速」下面。提示文字说明它同时影响提示音。

### 7.3 快捷键录制的界面状态

| 状态 | 按钮 | 说明行 |
| --- | --- | --- |
| 空闲 | 「重新录制」 | 「呼出 / 隐藏桌宠。被别的程序占用时这里会写明。」 |
| 录制中 | 「请按下组合键…（Esc 取消）」 | 「按下 Ctrl / Alt / Shift 加一个键。」 |
| 成功 | 「重新录制」 | 「已生效：Control+Shift+D」 |
| 失败 | 「重新录制」 | 「该组合已被其他程序占用，原来的组合仍然有效。」 |

失败时**保留原组合**，并把它显示出来——用户能立刻知道还能用哪个。

### 7.4 音量落在哪里

「总音量」不是 TTS 的 `vol` 参数，而是**渲染层的主增益**：

- `assistant.json` 的 `sound.volume`（0–1，默认 `0.8`）——与既有的 `sound.enabled` 同族；
- 主进程把它推给渲染层（`pet:volume`）；
- 渲染层的 `audio.js` 里 `masterGain.gain.value = volume`。

**不动 TTS 的 `vol` 参数**：那会让语音缓存按音量分桶（缓存键含 `vol`），
用户拖一次滑块就多一份缓存文件。

### 7.5 语音现在不受音量控制——这是要补的缺口

现状：`audio.js` 的 `playSpeech` 里 `source.connect(ac.destination)`，
**绕过了 `masterGain`**。所以提示音有音量控制，桌宠说话没有。
总音量要成立，语音必须也接进 `masterGain`。

## 8. 状态与持久化

### 8.1 `settings.json`

```js
{
  version: 1,
  position: null,
  modelId: 'haru',
  scale: 1.0,
  opacity: 1.0,
  visible: true,
  // —— 新增 ——
  autoLaunch: false,
  hotkey: 'Control+Shift+D',
  clickThrough: false,
  edgeSnap: true,
  dockEnabled: false,
  dock: null,          // 'left' | 'right' | 'top' | 'bottom' | null
}
```

全部走既有的 `sanitizeSettings`：

- `autoLaunch` / `clickThrough` / `edgeSnap` / `dockEnabled`：`typeof === 'boolean'` 才采纳；
- `hotkey`：字符串、非空、且**长度 ≤ 64** 才采纳，否则回退默认值。
  **不能截断**——截断出来的加速键串是个语法错误的东西，注册必然失败，
  而回退默认值至少是「能用的那一组」；
- `dock`：只认四个合法边名，其余一律 `null`。

### 8.2 `assistant.json`

```js
sound: { enabled: true, volume: 0.8 }
```

`volume` 的规整规则与既有的 `scale` / `opacity` / `tts.vol` **完全一致**：

- **越界夹紧**：`5` → `1`，`-1` → `0`；
- **非数值回退默认**：`'x'` → `0.8`。

（早先这里写的是「夹在 [0,1]，非法值回退 0.8」——两句话含糊，
实现时才发现「越界」到底算夹紧还是回退是有歧义的。
§9 的错误表已经写明「音量超出 [0,1] → `sanitizeAssistant` 夹紧」，
这里与它对齐，也与仓库既有的三个同类字段对齐。）

### 8.3 生效时机

`persist()` 之后调 `system.applySettings(next)`。**只有真的变了才动作**
（沿用 `appliedOpacity` 那个模式）：`persist` 在拖拽的每一帧都会被调用，
无变化时重复注册快捷键 / 重复写注册表是最热的路径上的无用功。

## 9. 错误处理

沿用仓库既有约定：**失败必须留痕（终端日志）+ 在界面上说得出来，不许静默。**

| 场景 | 处理 |
| --- | --- |
| 快捷键注册失败（被占用） | 设置窗口显示「该组合已被其他程序占用」；旧组合保留 |
| 快捷键加速键串非法 | 设置窗口显示「这个组合不能用」；旧组合保留 |
| 开机自启注册抛错 | 终端留痕；`autoLaunch` 改回 `false`；**`getState().lastError` 带上原因**，设置窗口显示出来 |
| 开机自启**关闭**方向写失败 | 终端留痕；`lastError` 带上原因；`applied` 保持旧值以便**重试**（磁盘与系统不一致不能当成功） |
| 停靠时找不到工作区 | 退回普通夹紧；不停靠 |
| 音量超出 [0,1] | `sanitizeAssistant` 夹紧 |
| 渲染层音量通道早于监听器注册 | 与既有的 `pet:soundEnabled` 一样，在 `onRendererReady` 时补发一次 |

## 11. 验收标准

1. 设置窗口「系统」分区有：开机自启、全局快捷键、鼠标穿透、边缘吸附、贴边隐藏。
2. 「语音」分区有音量滑块，0–100%，同时影响提示音与桌宠说话。
3. 开机自启默认关闭；打开后重启系统，桌宠自动出现。
4. 快捷键默认 `Control+Shift+D`，可在设置里改；被别的程序占用时设置窗口明确写出原因，
   且原来的组合仍然有效。
5. 穿透模式打开后，鼠标点击桌宠的位置落在桌面上；桌宠仍能跟着光标转头。
6. 拖到屏幕边缘会自动贴齐；开启「贴边隐藏」后松手会滑出屏幕只留 24px；
   拖那条边能把它拽回来；菜单里有「取回桌宠」。
7. 停靠状态重启后仍然停靠。
8. 所有失败路径都在终端留痕，且在界面上有对应说明。

## 12. 范围外与已知限制

- **混合 DPI 跨缩放比例显示器拖拽**：沿用既有已知限制，停靠逻辑不改变它。
- **停靠不支持每屏独立配置**：一个全局的停靠边。
- **快捷键不支持多动作分别绑定**：一个组合键对应一个动作。
- **开机自启不支持「静默启动」**：见 §3.3。
