# 视频素材整理指导

给「按 avatar.json 管理视频形象」准备素材用。目标只有一件事：

**你把视频和一份清单摆好，桌宠就能用——模型知道自己会做哪些动作、叫什么编号，
想做哪个就点名播哪个，不用改代码。**

与 Live2D / Spine 的分工：视频形象没有脸，表情就是一条视频 clip。
这份文档只管视频形象的分类、命名、标签与接线。

## 一、目录结构

一个视频形象 = 一个目录：

```text
我的形象/
  avatar.json        ← 清单（必需）
  webm/xxx.webm      ← 视频，相对路径由清单里的 file 引用（目录名随意）
```

视频格式：**透明 WebM（VP9 + alpha）**，9:16（建议 480×864）、24fps、≈5 秒。
绿幕怎么抠、参数怎么调，见 [`视频形象制作说明.md`](./视频形象制作说明.md)。

## 二、素材分类（category）

每条 clip 都有一个 `category`，四类，**纯属组织手段，不影响播放方式**——
它只决定提示词里「你能做出的动作」这张表按什么分组列给模型看。

| 分类 | 放什么 | 取材要点 |
|---|---|---|
| `idle` | 待机类：呼吸、歪头、重心换脚、环顾四周 | 首尾姿态**能循环或能自然转下一条**（见下「loop 与 one-shot」）。多条组成「待机池」随机轮播 |
| `emotion` | 情绪/表情类：大笑、打瞌睡、假生气、鼓腮 | 一次性。表达一种**心情**用的，幅度可以大一点 |
| `action` | 动作/手势类：打招呼、点头致谢、跳舞、拍手 | 一次性。表达一个**行为**用的，模型做任务、回应用户时会点这些 |
| `special` | 稀有/彩蛋类 | 一次性。低频出现，给模型「锦上添花」用 |

分不进去时：**拿不准就 `action`**，不会出错；分类只影响分组呈现。

## 三、命名与标签

- **`id`**：唯一；右键菜单的组名、`motion()` 的参数、模型点播的编号。
  建议小写字母 + 中横线（`sleepy`、`dance-latin`），≤64 字符，稳定不复用
  （换内容就换 id，别让 `laugh` 从「笑」变成「哭」）。
- **`label`**：菜单和提示词共用的中文显示名，**这是给模型看的**。写动作的内容，
  别写拼音、别写 id。好：`犯困打瞌睡`、`拍手打节拍`。差：`clip04`、`动作`、`新片2`。
- **`file`**：相对模型目录的路径；缺失写 `null`。导入时缺失条目会被跳过并提示，
  不会整个失败（一条可用都没有时才失败）。

## 四、loop 与 one-shot

- `"loop": true` = 循环播放，**只有待机类**用它。
- 一次性（one-shot，默认）：播完**自动回待机**——桌宠不会卡在动作的最后一帧。
  所以动作 clip 的**末帧姿态最好能自然回到待机站姿**（回到自然站立、结束于
  放松姿态），首帧也最好从待机姿态开始，衔接才不会跳。
- `idle` 绑多条时组成「待机池」：每条一次性播完按 `idleStrategy`
  （`random` / `sequence`，缺省 `random`）换下一条，`loop` 在此模式下失效。

## 五、semantic 绑定（可选，仅交互类）

`semantic` 把 clip 接到「不经过模型也会自动发生」的**交互**反应上：
待机、摸头、点身体、拖拽。它认的是固定的四个键，**不是 label**——
模型按 label 点播的路径（见下）不受影响。

| 语义键 | 自动接线的时机 |
|---|---|
| `idle` | 待机（待机池）。可绑多条 |
| `tapHead` / `tapBody` / `drag` | 摸头 / 点身体 / 开始拖拽 |

**情绪/表情类没有 semantic 键**：视频形象没有脸，情绪事件只调心情值，
不播任何 clip。模型想表现情绪（笑、拍手、跳舞……）时自己在 `<<META>>` 里
点名 `"action":"<id>"`——「你能做出的动作」那张表就在提示词里，识别靠的就是 label。

规则：

- 一个语义键只绑第一个（`idle` 除外，绑多条组成待机池）；重复的条目退回菜单与点播可见，不报错。
- **不绑任何 semantic 也能用**：提示词会列出全部 clip 的 `id=label`，
  模型想做哪个动作就在 `<<META>>` 里写 `"action":"<id>"`——
  绑 semantic 只是「不经过模型也能播」的接线，不是让模型能不能点播的前提。
- 建议：`idle` 池里放 3–6 条（呼吸、重心换脚、歪头、环顾四周）；
  `tapBody` 可绑撩头发/比心这类点身体的反馈；`tapHead` 可绑摸头的反馈；
  其余全留给模型自己挑。

## 六、新增一条 clip 的完整流程

1. 按 [`视频形象制作说明.md`](./视频形象制作说明.md) 抠好透明 WebM；
2. 放进形象目录（如 `webm/`），挑一个稳定 `id` 和看得懂的 `label`；
3. 在 `avatar.json` 的 `clips[]` 里加一条（参考 `miya` 的现成条目）；
4. **不用改任何代码**：下次桌宠加载这个形象时，提示词里会自动列出这条
   `id=label`（按 `category` 分组），模型就知道它存在了。

miya 现有的 clip 就是按这份清单整理的（`assets/models/miya/avatar.json`）：
待机×6（轮播）、情绪表情×8（打瞌睡/大笑/比心/假生气……）、
动作手势×13（招手/致谢/跳舞×9/哼歌……）。

## 七、快速自检

准备完素材后，按这几个问题过一遍：

- [ ] 每个 `file` 指向的文件真实存在？
- [ ] 每个 `id` 唯一、稳定、小写中横线？
- [ ] `label` 是给模型看的人话（内容，不是编号）？
- [ ] `idle` 类至少一条；一次性动作的首尾姿态能回待机？
- [ ] 角落透明没问题？（用 Electron 里实际播一次看，ffprobe 读不出 webm 的 alpha）
- [ ] 交互键该绑 semantic 的绑了（`idle`/`tapHead`/`tapBody`/`drag`）？情绪动作全留给模型自己挑（不写 semantic）？
