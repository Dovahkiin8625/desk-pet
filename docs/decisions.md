# 开发过程中的裁决记录

本文件记录在实现 Live2D 桌面宠物 MVP 期间，由控制器（在子代理实现与审查之间）代为做出的裁决。

每条包含：**决定了什么 / 为什么 / 判断错了的代价**。凡是标 ⚠️ 的，都是值得你亲自复核或推翻的。

---

## 流程与工程方式

### 1. 在 `feature/desk-pet-mvp` 分支上开发，而不是另开 git worktree
**为什么：** worktree 技能要求先征得同意才能创建，而 SDD 流程不允许在 `master` 上直接实现。分支同样满足后者，而 worktree 会把约 200 MB 的 Electron 与模型资源复制到第二个目录，还会让代码落在你编辑器打开的目录之外。
**代价：** 若你更想要 worktree 的隔离性，随时可以改。

### 2. 预检发现的缺陷回写进**计划文件**，而不只是记在账本里
**为什么：** 任务 brief 是从计划生成的；改计划能让 brief 自洽，避免把口头修正带进每一次派发。
**代价：** 计划文件与你批准的版本有出入——差异全部留在 git 历史里可复核。

### 3. 实现者发现的 brief 缺陷，一律回写计划后再继续
本项目里这条纪律重复生效：实现者三次发现我写的 brief 自身有缺陷（见下 #8、#12、#17）。**这是本项目最值钱的一条流程经验。**

### 4. 会变成后续任务真实故障的 Minor，合并进当轮修复，不留给最终审查
**为什么：** 「模型动作引用缺失的 .wav 会在每次点击时刷错误日志」「PNG 预乘 alpha 导致托盘图标有黑边」这类 Minor，放到后面只会变成更贵的返工。
**代价：** 偏离了「Minor 不进循环」的默认流程。

### 5. 修复**自身引入**的新缺陷，立即修，不延后
**代价：** 无。这条规则挡下了两个真实缺陷（纹理缓存的过宽清扫、`before-quit` 的同步处理器截断配置文件）。

## 语义与降级（模型抽象层）

### 6. ⚠️ 降级时**绝不按序号猜语义**——未映射的语义一律返回 `null`，只播动作
**为什么：** 官方样例 Haru 的表情表第 2 项是 `F02`（清单里映射为 `angry`），Natori 的**第 1 项就是 `Angry`**。按序号猜会让「摸头」触发生气的脸。spec §4.4 的降级表写的是「语义缺失 → 退化为播放对应动作；仍缺失 → 仅播动作」。
**代价：** 无语义映射的模型将**不再**有表情反应，只有动作。这是有意的取舍。

### 7. ⚠️ 连 `normal` 也不能按序号兜底——只能按**名字**匹配
**为什么：** 第一版实现给 `normal` 开了「例外」：用 `availableExpressions[0]` 兜底，理由是「普通表情不猜错任何情绪」。这个理由**是错的**——`availableExpressions[0]` 是序号，Natori 的首项就是 `Angry`，猜的正是错的。最终审查把它揪了出来。spec §4.3 自己的表就说 Natori 的 `normal` 是名为 `Normal` 的表情，而 Natori 确实有。
**代价：** Haru 那种 `F01…F08` 命名的模型在降级时**完全没有**表情，空闲时只播动作。

### 8. 清单优先于探测；探测只补清单没写的
**代价：** 无。

## 位置与多屏

### 9. ⚠️ 拆成两种语义：`clampToDisplays`（拖拽）与 `restorePosition`（启动恢复）
**为什么：** spec §5.5 要求「保存位置的显示器被拔掉 → 回落到主显示器可见区域内的右下角」，而原实现只把坐标夹到最近屏幕的可见边缘。根因是两种语义被塞进了同一个函数：拖拽时应该停在最近的可见处，启动恢复时应该回到主显示器默认位置。
**代价：** 多了一个导出函数。

### 10. `currentDisplays()` 必须主显示器优先
**为什么：** Electron 的 `getAllDisplays()` **不保证**主屏在首位，而 `defaultPosition` 依赖 `displays[0]` 是主屏。
**代价：** 无。

## 设置与持久化

### 11. ⚠️ `persist()` 必须过 `sanitizeSettings`；写入失败必须留痕
**为什么：** 否则渲染层传来的越界值（例如 `opacity: 1.5`）会留在内存里而落盘时被夹紧——内存与磁盘不一致，越界值还会被 `win.setOpacity()` 用上。写入失败静默吞掉，则用户「改了设置没生效」却既无现象也无日志。
**代价：** 无。

### 12. `settings.json` 改为写临时文件再 `rename`（原子写）
**为什么：** 普通 `writeFile` 在写入过程中被杀会留下 0 字节文件，下次启动静默重置位置、形象、缩放与透明度。
**代价：** 无。

### 13. `modelId: 'haru'` 作为设置默认值**保留**
**为什么：** 这是「默认选哪个形象」的**数据**，不是分支逻辑，与「模型名不得出现在通用逻辑代码中」的约束不冲突；而且默认值本就该在设置文件里。
**代价：** 无。

## 渲染与测试

### 14. ⚠️ 撤回「像素采样行宽要乘 `renderer.resolution`」这条修正
**为什么：** 那是**审查者（我）提出的假前提**——`extract.pixels()` 对 DisplayObject 走 `generateTexture()`，按 `getLocalBounds` 创建 RenderTexture 且**不传 resolution**，故行宽恒为 bounds 宽度（`settings.RESOLUTION = 1`），与 `renderer.resolution` 无关。原来的写法在任何分辨率下都是对的；「修正」反而在 150% 缩放的 Windows 11 上取到躯干而不是头部。最终改为从 `extract._rawPixels()` 返回的 `{pixels,width,height}` 取几何，不再依赖任何外部假设。
**代价：** 无。

### 15. 置顶断言必须先探测环境是否支持置顶
**为什么：** `isAlwaysOnTop()` 在没有交互桌面的 Windows 会话里恒为 `false`（连最小 stock Electron 应用也是），无条件断言会让整套测试因环境而变红；而无条件跳过又会让断言静默变成空操作。探测 + 跳过时留痕是唯一两种环境都正确的做法。
**代价：** 无。

### 16. 悬停也重置空闲计时
**为什么：** 空闲动画是给「用户走开了」准备的；鼠标还在桌宠身上动时，桌宠正被看着，不该自说自话。
**代价：** 桌宠在你一直动鼠标时不会自己演 idle。

### 17. 修「计划里的代码」时，实现者必须**照抄计划**而不是自己重写
**为什么：** 本项目里实现者照抄计划三次撞上计划自身的 bug（漏 import、`before-quit` 同步截断、未知动作组返回未经验证的 spec）。这三次都是实现者发现的——**brief 是唯一真相源，但真相源本身可能有错**。

## 已知的 MVP 限制（已写进 README「已知限制」）

- ⚠️ **混合 DPI 跨缩放比例显示器拖拽**：增量取自 `window.screenX`（DIP 单位），窗口跨到缩放比例不同的显示器上时增量在两套单位间混算，会有一次性跳变与后续速率误差。单显示器 100% 缩放下精确。无法在本机复现，未自动化覆盖。
- ⚠️ **`app://` 服务整个项目根目录**：`app://bundle/package.json` 可被取到（点开头的路径段被拒、目录穿越被拦）。渲染层只加载自己的模块与模型资源，没有不可信代码在跑。收紧需要重新设计资源布局。
- ⚠️ **`npm audit` 的 2 个 critical 不修**（`gh-pages` 原型污染，来自 `pixi-live2d-display@0.4.0` 误列的文档发布工具链依赖）。`npm audit fix --force` 会把 `pixi-live2d-display` 降到 `0.3.1`，**破坏 Cubism 4（`.moc3`）模型支持**。缓解：该包仅开发期安装，运行期不进 bundle。
- **`window.__pet.setIdleMs` / `window.__pet.switchModel` 是生产环境可见的测试/诊断钩子。**
- **托盘的 `setContextMenu` 是否真的被调用无法断言**——Electron 不提供托盘枚举。
